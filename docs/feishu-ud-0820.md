# v0.8.20 飞书 UD 弹层误判修复

用户的 v0.8.19 报告中，87 个字段有 75 个匹配结果，但全部被“前一控件的候选列表仍未关闭”拦住。实际展开采集提供了 UD 下拉选项、地域树、月份日历和学校输入框结构，能够定位两处扫描误判。

## 原因与修改

- 学校的 `.ud__select__dropdown-open` 包着输入框，点击前后都存在，内部没有实际候选列表。旧的宽泛 dropdown 选择器把它当成弹层；关闭判定始终失败。现在状态外壳不参与弹层观察，归属检查也拒绝包含原触发器或本地输入框的容器。真正 `.ud__select__dropdown` 与其嵌套菜单作为一个面板处理；ARIA 同时指向外层和内层也合并为一个面板。
- 真实 Formily 字段带有 `.ud-formily-item-control-align-left`。旧的 control 子串判断跨过整个字段，把所属标签丢掉。现在只沿 `.ud-formily-item-control`、`-content`、`-content-component` 的确切类名上行。手机号与手机区号共享本条电话标签，不借用前一条“姓名”。诊断采集采用相同边界。
- UD 下拉补上实际菜单项 `.ud__select__list__item`、选中显示 `.ud__select__selector__selectItem`、地域树标签 `.ud__tree__node__label`。普通选择器点击外层表面；学校点击真正的可编辑输入框。搜索输入值仍不算已选择内容，选项点击必须导致面板收起并保留结果。
- Escape、失焦后仍有列表时，可以浏览器真实点击本字段的非交互标签区域。标签内有按钮、链接、输入或关联的 `label[for]` 则拒绝这个方式；点击前再次确认原节点、位置和命中范围。没有安全目标时继续停止，不猜邻近按钮。
- 真实 UD 月份使用 `01月` 到 `12月`，年份表头是 `2026 年`，可点击的年份标题是 span。日期适配器识别这些写法，选择年份列表和月份格，面板提交且失焦后保留目标值才计入成功。捕获的表头箭头只能在唯一表头与明确的两个按钮内导航；点击后检查年份方向。没有足够语义的未知日历仍停止。
- 真实弹层确实无法关闭时，保留停止逻辑；后续匹配字段标成“尚未尝试”，不计入“写了但页面没认”的控件问题。重新填写前仍尝试收起本轮已知的关联面板。
- 自动采集先保留不同控件形态的名额：有限选项、可编辑学校、地址搜索、普通日期、成对日期及不同日期精度，随后才补同类字段。重复下拉不再挤掉所有区间日期样本。打开前快照保持当时状态，不回填后来的打开结果。

## 验证

`tests/fixtures/feishu-ud-captured.html` 使用采集得到的 UD/Formily 类名、嵌套、月份文字和指针事件，并使用匿名字段、合成的事件与状态逻辑。它不是登录后的网页副本。

`tests/feishu-ud-captured.cjs` 运行生产扫描、选项预读、完整填写按钮、浏览器真实输入及最终页面读回：

- 正常流程写入姓名、手机、邮箱、性别、学校、学历、月份日期和评价，菜单关闭且原资料树不修改。
- 全屏表单盖住所有裸 body 点击点时，仍能在本字段安全标签处收起菜单。
- 学校空搜索框的状态外壳不作为弹层，诊断保留正确 Formily 字段上下文。
- 列表真的收不起来时，后续项显示未尝试，不产生几十项控件写入失败。
- 搜索结果点击不提交、日期格点击后不提交，以及年份翻页方向相反都不报成功，也不把草稿回收进资料。

同时检查单元测试、原 UD 日期确认/重渲染/区间保护，以及已有下拉、来源归属、浏览器输入和结构采集回归。

本轮依据实际结构修复，但尚未在用户登录后的 NIO 页完成整表验证；地址树的动态数据和其他未展开日历仍可能需要后续采集。
