# v0.8.11：旧资料形状与来源归属

基于 v0.8.10 修复。对用户提供的 JSON 备份和 Excel 逐条核对：两份文件包含的 94 条字段一致。下面的例子和测试均使用匿名资料，安装包不包含用户备份或个人信息。

## 改动

| 现象 | 修复 |
| --- | --- |
| 电话字段保存“13800000000（微信同号）”，网页手机号始终无值 | 只格式化明确的电话字段，保留字段来源身份。允许有限的“微信同号”备注及国家代码写法；不从邮箱、QQ、微信账号取号码，不取其他人的电话，不选择多个候选。AI 漏匹配时规则补空。 |
| 错误职务候选指向“校园2”整段文字，导致另一条正确描述也被拒绝 | 建立记录归属前核对字段用途。未通过用途检查的职务不提供归属依据；同值职务不能单独区分多条经历，须有名称或可核验原文。描述确认记录后，再补该记录的职务。 |
| 旧校园整段中写有“某协会干事”，结构化记录漏了职位字段 | 仅当整句的第一分句是唯一组织名称加明确职务，且结构化记录没有职位时，补出带来源编号的临时事实。引用整句与组织字段的两个来源；多个组织、同名组织、多个段落候选及仅在后文出现的工作职责均不提取。 |
| “具有良好的英语听说以及阅读能力”被判没有听说水平来源 | 支持有限的明确能力句式，并核对语种与否定、冲突。该句可证明听说良好；不证明综合掌握程度，也不证明写作能力，因此不会填读写良好。考试分数继续不换算能力。 |
| 硕士与学士字段放在同一条旧“待归类资料”下，同校时间可能串用 | 对填写时的来源视图按明确字段前缀分阶段，学校、专业、区间端点保留各自身份。存储的字段编号、键与原值不改；用户明确命名的记录不拆。“学士”前缀不生成“本科学历”。旧阶段映射的记录身份对不上时回到本次匹配。 |
| 明细显示来源拦截，顶部却说没有发现问题 | 汇总未解决的来源拦截与未完成写入；另列未给出值的数量。安全来源补成功的字段不再计为未解决拦截。填写状态提示相同的未解决项，联系方式护栏拒绝也进入诊断。 |
| 来源写到具体日，AI 只给月份，日历却补成 1 号并提示简历只有月份 | 已验证为同月日期时，优先保留来源中的具体日。只有来源确实只写到月份时才保留补 1 号的核对提示；月份控件仍按月份精度填写。 |

## 验证

旧代码先运行六项针对资料形状的回归测试，六项失败；修复后通过。增加教育阶段来源隔离与日期精度测试后，全套 113 项单元测试通过。

完整填写回归使用生产扫描、后台校验、填写控制器、浏览器输入和最终页面读回，验证电话备注、两个同值校园职务、错误候选不影响正确描述、旧原文提取、听说能力及未填写的综合能力和读写。共验证写入 23 项，已有内容保护 1 项；生日的月份目标恢复来源中明确的 17 日，无明确综合水平的提案保留来源拦截提示。继续覆盖四个经历日期端点、同名不同年份奖项、描述原文及不被日期误填的复选框。

普通表单回归验证来源拦截汇总、补成功后的提示消失、未提供值计数和无读回值的执行失败提示，同时覆盖异步联动、人工已填内容与节点重建。实际公开发布的 Phoenix Select、SelectList、UnmodeledLayer 3.3.55 组件验证学历、语言、水平选择及最终 DOM 值、禁用和重复选项等。

## 更新与仍需补充的资料

解压覆盖原插件目录，在扩展管理页重新加载，确认显示 0.8.11，再刷新招聘表单。现有资料与设置可以继续使用，无需重新导入。沿用现有浏览器点击与输入通道。

没有保存的事实继续留空：本科对应记录的明确学历、校园起止时间、求职意向、证件信息及奖项级别等，需在对应资料记录补充。只有英语阅读能力不能代替读写能力；综合掌握程度也应单独保存。
