# v0.8.7：凤凰触发器漏扫、复选框误匹配与同名获奖

在 v0.8.6 基础上修复，保留资料树和既有日历驱动。本次没有添加截图识别。

## 原因与修复

### 正常触发器被当作弹层排除

v0.8.6 将 `.phoenix-unmodeled-layer__content` 列入弹层选择器，扫描时排除了它内部的控件。第一方发布代码 [@beisen-phoenix/unmodeled-layer 3.3.55](https://www.npmjs.com/package/@beisen-phoenix/unmodeled-layer/v/3.3.55) 的 `cjs/index.js` 中，`renderChildren` 使用这个类包裹触发器；`cjs/Layer.js` 的弹出内容另用 `.common-unmodeled-layer__layerContent`。这解释了日期和下拉整类漏扫，而复选框仍在字段表中的现象。

现在以选项列表、日历和其他明确面板结构识别弹层，不再仅凭通用容器类排除字段。只在面板外围不包含其他表单控件时扩展到浮层容器，以读取列表旁的搜索框。当前控件打开后，仍须确认唯一关联面板，不能使用全页同名选项。

相同规则用于填写和结构采集；控件规则版本更新为 2。

### “结束时间”旁的复选框被按日期处理

原日期判断对所有非原生日期 input 读取标签，复选框继承“结束时间”时也会命中。通用 picker 扫描还可能把内部 checkbox 升级成日期字段。

现在：

- 日期文本判断只接受文本、搜索输入；picker 内部排除复选框、单选和已归入下拉的输入。
- 复选框优先读取自己容器内的“至今”等说明，避免继承外层日期标签。
- 匹配、日期执行和普通执行都检查控件类型。复选框不接受日期或普通文本。
- 合法勾选必须有用途对应、记录一致的来源；用实际点击改变状态，按 `checked` 核对，不往 `value` 塞文字。
- 勾选后节点被网页重建时，重新定位再核对；被遮挡等操作失败只报告当前字段。复选框自身说明不会因另一条已勾选的同名说明而丢失。
- 同意、承诺和协议继续由本人确认；已有勾选保持原设置。

### 同名获奖第二、三条没有名称来源

旧导入资料使用 `奖项名称-获奖时间 (2)/(3)` 区分记录。原名称展开只识别严格以 `-获奖时间` 结尾的键，遗漏后缀记录。

现在根据旧键中的奖项名称和所属记录标题交叉核对，为每条记录补出可引用的名称；编号后缀不进入名称值。不修改用户已存事实。同名名称仍可能存在多个候选，因此必须引用明确的字段编号；获奖日期继续检查是否与本条记录一致。

## 验证

- 94 项单元检查，包括三个同名奖项从旧资料迁移到独立记录、日期串条拦截、复选框拒绝真实日期来源。
- 同一匿名页面分别加载 v0.8.6 与修复代码：原版只扫到 4/12 项，8 个下拉全部漏掉；修复版扫到 12/12 项，保留两个独立复选框。
- Phoenix 浏览器回归增加普通触发器容器、浮层内独立搜索框、需要真实事件的至今复选框，以及日期容器内复选框不升级成日期。
- 完整填写流程覆盖触发器容器、两条项目的四个日期端点、同名奖项三个年份、原文描述组合、保留已有学历和复选框、最终页面值核对。
- 现代 Ant、Element UI、iView 的已发布组件日期和下拉回归。
- 表单扫描、异步下拉、ATSX 日期、浏览器输入、控件采集及资料树界面回归。

测试中的模型回复和扩展存储使用匿名替身；扫描、来源校验、控件执行、浏览器输入及最终读回使用生产代码。第一方组件测试使用固定版本的实际组件。未把这些结果表述为用户登录招聘页面上的实测。

## 更新

解压新版包并覆盖原扩展目录，在扩展管理页重新加载，然后刷新招聘网页。自定义控件填写时勾选“实验：浏览器层点击与输入”。无需重新导入资料。
