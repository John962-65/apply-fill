# v0.8.15 拆分年月与网页归属修复

108 字段日志中，75 项被拦截的主要原因在网页结构识别：开始年月与结束年月的内层容器被误识别为两条经历；“项目经验”标题漏认，七条项目沿用了前面的“实习经历”；“奖项名称”未用作获奖记录锚点；独立自我描述沿用了语言能力板块。

本版在 v0.8.14 的有依据推导规则上修复这条链路，不改写已保存的简历资料。

## 网页结构与来源

- 支持“项目经验”“实习经验”“工作经验”“研究经历”“求职意向”“自我描述”等标题及既有标题。只有正文表单的标题参与归属，侧边目录和控件标签不充当板块标题。
- 拆分年月先识别为日期组成部分，再识别外层重复经历。内部年/月或起止两端不能成为经历条目；同一个兄弟容器下的不同记录结构按各自签名匹配。
- 开始/结束方向来自明确标识或位于两端之间的“至、到、横线”等范围分隔符。不凭四个控件的数量猜方向；缺少明确方向时停止这些年月，其他字段仍能处理。
- 年、月分别从同条记录、相应用途的完整日期提取。例如 `2024-09` 对应 `2024年` 和 `9月`，保留完整日期的来源编号。不会从电话、描述中的数字截取年月，也不会用结束日期补开始日期。
- “奖项名称”“奖励名称”可绑定获奖记录，日期随后引用该记录。独立自我描述归入自我评价。项目里同时存在“职责”和“项目中职责”时，短输入的“职责”作为项目角色，另一项仍引用职责原文。
- 真实实习仍使用实习/工作来源，不把科研项目批量当作实习。

## 操作、读回与采集

支持原生年月下拉，以及按当前弹层选项、通过浏览器真实点击操作的自定义下拉。`年、月、YYYY、MM` 是占位项；`09` 与 `9月` 在月份用途内相等。多个等价选项、无等价选项、被禁用的选项会停止选择。

一组起止年月四项必须有成对来源，且属于同一条资料记录；组合日期检查开始不晚于结束。完成填写后读取实际页面的四项，控件重渲染时重新定位。年月各自正确但组合区间倒置，也不会计为成功。人工已有内容继续保留。

采集时把拆分控件合并为完整的 `YYYY-MM`，保存“开始时间”“结束时间”或“获奖时间”，避免把一个月份单独归档成完整日期。字段对照表明确区分“年”“月”并说明取值来源；结构快照身份也包含日期部分，旧完整日期身份保持兼容。旧错误板块和条目映射无法匹配修复后的身份，相关字段重新走当前来源校验。

## 验证

验证使用匿名表单、模拟模型响应和真实生产扫描/校验/填写代码。没有连接用户登录的招聘网页，也没有调用收费模型。

| 验证 | 结果 |
| --- | --- |
| 141 项单元验证 | 通过，包括同条年月来源、错误端点、跨记录、数字冒充日期、出生日期本人归属、重复选项与奖项名称别名 |
| 108 字段复现表单：两条教育、七条项目、五条获奖 | 94 项有来源的值实际写入并通过最终 DOM 核对；14 项未提供事实保留空白 |
| AI 漏给全部 46 个年月部分 | 由已确认记录的日期来源补齐，最终仍为 94 项 |
| 每次修改替换整条经历容器 | 重新定位并核对最终值通过，资料树未改写 |
| 采集回资料 | 23 个日期合并为完整年月，未归档零散年份或月份 |
| 倒置起止、跨记录、缺少月份、缺失范围分隔符 | 拦截或在最终读回报告异常 |
| 自定义年月下拉 | 正常、重渲染与重复月份场景通过；实际操作使用可信 CDP 点击，无无关选项点击 |
| 已有回归 | 普通表单、同义规则、Phoenix 下拉和日期、异步下拉、资料管理及上传核对通过 |

可执行 `npm test`、`npm run test:split-resume`、`npm run test:split-combos`。浏览器回归需要 Playwright 和 Chromium；可通过 `CHROMIUM_EXECUTABLE_PATH` 指定浏览器。

真实招聘站仍需用新版复测。如果仍有漏项，可导出插件的“实际网页结构”文件，连同新版字段对照表定位具体 DOM。

## 升级

完整解压 `apply-fill-v0.8.15.zip` 并覆盖原扩展目录，在 Chrome/Edge 扩展管理页点击“重新加载”，确认显示 0.8.15，然后刷新招聘和资料管理页面。扩展 key 保持一致，原资料树和配置继续保留，无需重新上传简历。保持原扩展安装记录即可。
