# v0.8.17 拆分日期与下拉读回

用户 v0.8.16 日志包含两类失败：教育、项目日期在匹配后被“未确定拆分年月的起止方向”拦截；获奖年月及其他下拉框在点击后未确认选中。截图中的学校、专业和学历实际已经显示，说明“未确认”也可能来自读回失败。此次修复使用日志的类名线索和匿名网页复现，尚未取得该登录页的实际 DOM，因此不宣称已在该私有页面验证。

## 已确认的代码问题

1. 起止方向解析只检查元素叶子。`年 月 - 年 月` 中的横线若直接是文字节点，便无法识别；四个字段因此全部被标记为方向不明。
2. 下拉预读最多保留 60 个选项，且明确标注 `optionsComplete=false`。日期分量校验却忽略这一标记，把年份列表前 60 项当成完整范围；后面的正确年份会在操作之前被丢弃。AI 漏填时的本条日期补空也受同一问题影响。
3. 通用结构下拉为防止把搜索文字算成选择，仅接受已知显示节点、选择 ID 或已确认的输入框文字。未知组件选中后清空输入框、在旁边显示文字时，会错误读为空。
4. `sd-Input/Select-container-*` 可能使用 `label` 作为组件外壳，内部的当前选中值不是字段名。另外，普通字段“工作经验”若用样式化 `div` 标题显示，会被识别成“工作经历”板块，影响后续的最高学历等字段。

## 修改

- 在仅包含一组日期控件的共同容器内读取可见文字节点。真实分隔符必须位于第二和第三个日期分量之间，且不来自控件、选项菜单或隐藏文本；明确的开始/结束标签仍优先。
- 不以不完整的选项预读否定格式正确、有本条日期来源的年月。填写时仍只点击实际出现的唯一等价选项，保留年份、月份范围检查。
- 读取关闭后控件内独立显示的文字，排除菜单、输入框、图标、占位语、字段标签与帮助信息。输入框为空、单独显示选中名称的情况可以核对；可编辑搜索文字及其镜像仍需要选择 ID 或完成点击的凭据。只读框可保留人工已有值。
- 存在隐藏选择 ID 时，点击必须实际提交该 ID；未提交、延迟回退、重复选项和未关闭弹层仍不计成功。
- 跳过 `sd-*` 的组件外壳标签和单个字段卡片里的“工作经验”等字段标题。`apply-fields-*` 等整体板块容器不受这条排除规则影响。
- `sd-Select-container-*` 的哈希后缀能出现在结构诊断中；目录仅增加观察线索，操作继续由局部观察、点击和核对控制器完成。

## 验证

- `npm test`：日期完整/部分选项、日期来源、同记录补空、起止用途、跨记录拒绝等单元回归。
- `npm run test:split-resume`：108 个字段，生产扫描器、匹配校验、填写和最终读回；两条教育、七条项目、五条获奖、语言及个人信息。原生普通、AI 漏填日期、控件重建，以及 `sd-*` 独立显示、输入框显示、选中后重建共六种模式。每种检查 94 个有来源字段和 23 条完整采集日期。
- 三种 `sd-*` 模式使用真实 Chromium CDP 点击/输入，年份菜单包含 201 项，纯文字横线位于嵌套端点之间；独立显示模式故意让 AI 不给出全部 46 个年月分量，检查本条资料补齐。
- `npm run test:sd-choices`：人工已有显示、人工只读选中、搜索镜像、隐藏 ID 未提交、组件不接受点击、延迟回退、隐藏或菜单内假分隔符七种场景。
- 既有自动补全、普通表单、Phoenix、控件采集和来源规则回归一并检查。测试不会提交申请，资料树保持原样。

## 安装

解压覆盖原目录，在扩展管理页重新加载插件，再刷新招聘网页。自定义下拉保持“实验：浏览器层点击与输入”开启。版本号为 0.8.17，扩展 key 和资料格式未改变；旧资料树、设置、映射及备份继续使用。

如果该页面仍失败，插件的“采集网页结构”导出结果能确认它实际的选中显示节点、弹层归属和日期分隔符。截图及日志无法证明网站最终保存的内部状态。
