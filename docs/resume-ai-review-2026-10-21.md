# AI 简历解析与核对界面改进

日期：2026-10-21。针对“解析不准确、确认信息不直观、不清楚哪些需要确认”的反馈。

## 一、实现内容

- 将已有的独立 LLM 提取能力接入工作台主入口。选择 PDF 后可直接点击“AI 解析简历”，先在本地提取文字，再交给用户配置的模型进行结构化识别；“仅本地解析”作为备用入口。
- API 配置入口放在导入区旁，支持兼容 Chat Completions 的 Base URL、API Key、模型名称。点击“保存并授权模型服务”会保存当前设置并取得浏览器域名权限；配置未保存时禁用 AI 解析。后台发送前重新检查真实权限。
- 模型接口明确拒绝 `json_schema` 时尝试 `json_object`，仍不支持时尝试提示词 JSON；这些兼容尝试有明确上限。密钥错误不会通过格式回退反复发送，请求失败时保留本地结果。
- 审核区改为个人信息、教育、工作、项目、技能的分组卡片。顶部显示需补充/修改、待核对、已确认数量，支持筛选、分类跳转与定位下一项。
- 每项直接显示原文和页码，提供“核对无误”“不使用这项”。允许核对整段经历或个人信息后批量确认。空白可选字段无需确认；必需的缺失字段、异常邮箱/日期显示具体处理原因。
- 支持直接补充漏掉的字段和整段经历。补录或修改的内容仍是待核对状态；清空可选日期会移除该事实，便于保存并稍后补充。修改异常字段时，字段保留在当前筛选中，避免打一个字就从界面消失。
- 把 JSON 预览移入高级展开区，普通用户通过表单核对。支持查看、修正 PDF 提取文字并重新解析。项目描述中的“公司”“项目”等词不再轻易触发新经历；右对齐日期保留与对应行的关联。
- 修复工作台初始化刷新迟到时覆盖新附件与解析草稿的问题；解析结果绑定当前输入版本，丢弃过期返回结果。
- 加强 AI 原文校验：相同数字不能为其他编造的表述提供证据；日期允许格式规范化，但不把两个日期的数字拼成新日期，不推断“至今”。不再写入固定的伪置信度。模型返回结果保持待核对，确认并保存后才用于自动填写。

主要文件：`entrypoints/workbench/App.tsx`、`ReviewPanel.tsx`、`style.css`，`resume/review/editor.ts`，`resume/extraction/`，`background/ResumeExtractionService.ts` 和 PDF 布局/本地解析器。

## 三、使用步骤

1. 解压最新 [Chrome 安装包](../apps/extension/.output/applyfillextension-0.1.0-chrome.zip) 或 [Edge 安装包](../apps/extension/.output/applyfillextension-0.1.0-edge.zip)，在扩展管理页面重新加载；从源码构建可运行 README 中的打包命令。
2. 打开工作台，在导入区点击“配置 AI 解析服务”，选择云端解析、勾选允许使用 AI，并填写服务的 Base URL、API Key 和模型名称。Base URL 例如 `https://你的模型服务地址/v1`，不包含 `/chat/completions`；模型名称按服务提供方填写。
3. 点击“保存并授权模型服务”，确认浏览器域名授权，然后选择 PDF，点击“AI 解析简历”。简历文字包含个人信息，会发送到你指定的模型服务；“仅本地解析”不发送简历文字。
4. 在“核对简历信息”先处理橙色缺失/异常项，再对照可见原文核对其他信息。信息有误可直接修改，遗漏的经历可以补录。点“核对无误”或确认本段，再“保存到简历”。
5. 回到招聘页面授权并开始填写。未核对或选择不使用的内容不会自动填写，可先保存草稿并稍后继续核对。

## 四、限制

- 当前 AI 解析接收提取出的 PDF 文字，扫描件/纯图片 PDF 仍需 OCR 或视觉模型，暂未实现。
- AI 不能保证准确；无原文证据的字段会被丢弃并提示，确认状态不会由模型自动授予。
- 不同模型的上下文限制、服务额度和输出质量需要按实际服务验证。此版本支持兼容 Chat Completions 的接口；其他协议需单独适配。
