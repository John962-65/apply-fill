# v0.8.10：学历来源与记录内漏匹配

基于 v0.8.9 继续修改。最新日志的日期、获奖时间、语言类型均已写入并读回；剩余问题主要涉及来源核验和漏匹配。本次沿用现有控件操作通道。

## 改动

| 日志现象 | 处理 |
| --- | --- |
| “硕士研究生”被判无来源，而资料中有“学历＝硕士” | 核验时传入网页字段用途，用有限的同义值表匹配。同一学历可有不同写法；学位另用一套表，学士不证明本科学历，博士后不等于博士，研究生不自动区分硕士与博士。 |
| 全局“学历＝硕士”可能被填到每条教育记录 | 只有本条记录已有的教育来源证明其硕士层次，才允许使用唯一的全局学历。每条记录自己的显式学历优先；不按条目序号猜层次。 |
| 旧缓存可能绕过新的学历用途校验 | 学历／学位映射复用时重新核对用途；教育页面不直接复用全局最高学历映射，回到本次匹配取得记录证据，也不学习这类跨分组全局映射。 |
| 两个学校输入标签退成“请输入” | 表单项查找扩展到 32 层并去重；普通样式化标签通过唯一控件作用域查找。遇到其他字段停止向上借标签，排除弹层、帮助文字与格式占位串。 |
| 校园描述已填，职务未提供值 | 名称、职务或可验证原文描述唯一确定记录后，只取同分组、同记录的显式职位字段补空。多个职位候选、跨记录、跨板块和记录冲突都停止。 |
| 语言类型已填，掌握程度漏匹配 | 从该语种记录的明确字段或旧“英语水平”中的字面能力分句补空。听说、读写分别处理；综合良好不能填满三个字段，六级等考试成绩不换算能力，混合语种的模糊水平不复用。 |
| 没有来源编号的截取可能命中多条资料 | 部分文本回查保留多候选歧义，来源护栏拒绝模糊复用。记录身份同时包含简历分组和记录。 |

对照表显示“同义写法”“截自”“组合自”等来源关系。记录补空计入“规则补空”，仍经过正常字段校验、页面操作和最终读回。

## 验证

单元测试覆盖同义值、用途错配、同校多学历、全局学历错误复用、校园职务缺失及冲突、不同分组、语言能力分句与考试分数。实际公开发布的 Phoenix `Select`、`SelectList`、`UnmodeledLayer` 3.3.55 组件验证从后台匹配结果选择“硕士研究生”“大学本科”“英语”“良好”，并核对最终 DOM 值、禁用选项、重名选项、已有值保护及采集归属。匿名学校输入使用 20 层包装与普通 div/span 标签，也检查不借邻居标签。

完整填写测试走生产扫描、后台来源护栏、填写按钮、浏览器输入及最终页面读回；第二条校园描述先确认记录，再补该记录的职位。保留日期、同名不同年份奖项、描述原文和“至今”复选框的回归覆盖。

## 更新与资料补齐

解压覆盖原插件目录，在扩展管理页重新加载，再刷新招聘表单；继续勾选“实验：浏览器层点击与输入”。无需重新导入资料。

安装包显示修正：移除沿用的旧 `version_name`，扩展管理页直接显示 `version` 中的 0.8.10，避免显示名称和实际版本不一致。

本科那条记录若只有“学位＝学士”，应补上明确的“学历＝本科”。手机号、证件、校园时间、奖项级别以及听说读写等未保存事实继续留空；不会从邮箱、学校、活动描述或考试分数推算。
