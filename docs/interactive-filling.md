# v0.6.4 交互式下拉填写

自定义下拉改为“打开 → 观察实际选项 → 搜索或滚动 → 点击 → 读回核对”。AI 仍负责根据简历决定字段目标值，交互执行器负责按页面实际状态执行；本版没有增加每次点击的模型请求，也不是截图视觉代理。

- 增加诊断中出现的 Phoenix 容器和触发器识别，避免把其内部搜索框当作普通文本框。
- 优先通过 aria-controls / aria-owns 关联当前弹层；没有关联时，仅接受本次打开后唯一出现的面板，不在全页面搜索同名选项。
- 每次点击前重新读取选项，等待异步结果；支持以“省 / 市”形式给出的分级路径。
- 搜索文字不作为选中证据；选中后检查显示值，关闭面板后再次检查，最终仍执行整页读回验证。
- 控件重渲染后按原有字段身份重新定位；不唯一则停止。已有内容不覆盖，同名候选不猜测。
- 每级最多 14 次尝试，循环总时限 15 秒（正在进行的等待可能略超出），失败会记录具体原因。操作记录进入字段诊断报告。

## 验证与边界

`npm test`：65 项来源校验、映射及资料管理等单元测试。

`npm run test:forms`：原有表单回归，并验证 Phoenix 容器只扫描为一个下拉字段。

`npm run test:combos`：异步挂载、无关联属性的唯一新弹层、远程搜索、分级选择、控件重渲染、同名冲突、点击无效、保留人工内容；各场景都检查不会点击旁边同名菜单。

测试是匿名模拟页面。Phoenix 容器类名来自诊断，选项结构采用通用语义模拟，不代表已经在 vivo 登录后表单完成实测。普通页面脚本点击仍属于合成操作；若平台明确只接受真实用户事件，本版不会绕过该限制。无可识别语义的绘制控件、特殊多选或日期面板也不保证能由此执行器处理。

## 更新

解压新包，在浏览器扩展管理页加载解压后的 apply-fill 目录；已经从同一目录加载时更新文件后点“重新加载”。再刷新招聘页面，使用原有“一键 AI 填写”入口。提交前检查失败标记和字段报告。
