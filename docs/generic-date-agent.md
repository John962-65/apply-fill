# v0.9.0 通用日期交互 Agent：规则优先 + AI 失败接管

本轮解决的核心架构限制：此前日期字段只给模型「调用适配器 / 停止」两个候选，全部日历操作由预先编写的平台适配器控制；遇到不认识的日历弹层时，模型既看不到面板结构，也没有可用的动作，只能放弃。0.9.0 把弹层观察、候选生成与逐步执行接进已有的交互引擎——AI 第一次能根据网页真实状态逐秒决定下一步，而不再要求开发者为每种日期组件写适配器。

## 接口改造（先于 Agent 本体）

- **`calendar-agent.js` 支持动态契约**：`fill({..., contract})` 新增可选参数。契约字段双形态——CSS 选择器字符串（目录契约原样兼容）或 **resolver 函数**（每次访问对当前面板重新解析，不缓存节点，杜绝"临时类名在重渲染后失效"）。`validateContract` 按声明的网格推导必需导航链，缺链即返回 `null` 交回调用方，绝不猜测。未提供 contract 时原路径不变。
- **`date-precision.js` 日期精度模块**：只信页面证据——控件类型与占位符写法 → 日历网格结构 → 提交行为（仅用于最终验证）。资料值形态**绝不参与推断**；证据冲突或不足时返回 unresolved，Agent 停止而不是按简历日期猜。资料值一律按页面精度归一化（资料存 `2024-09-01`、网页只要 `2024-09` 时按月填、按月验）。
- 现有四家适配器（ud/atsx/phoenix/calendar）内部逻辑未动；它们后续可从诊断里拿到精度判定依据，再按实证收紧。

## 通用日期 Agent（`date-agent.js`）

**结构分类器**（无平台类名依赖）：按格子文字与密度识别年/月/日网格（复用现成 `monthNumber`），解析表头年月（含「2026年10月」合并式表头），翻页按钮按 aria-label/文字识别，无标签时以几何箭头配对兜底——方向一律以点击后日历状态变化验证，不凭箭头朝向断言。分类产物是一个**活的 CalendarView**：每个访问都现查现用，绝不缓存节点。

**双策略**：

1. **合成契约快路径**：分类高置信时，把结构合成为与 control-catalog 同形的日历契约（三种视图无条件声明、resolver 活解析），交给现有 `ResumeProCalendarAgent` 驱动——**0 次模型调用**，未知但结构规整的日历约 250ms 完成。
2. **AI 逐步接管**：分类不置信或快路径失败时，走 `ResumeProInteractionAgent` 循环。候选分两层——tier-1 语义动作（pick-year/month/day、open-year/month-view、nav-*、confirm、type、wait、stop，全部只在目标唯一匹配时出现）+ tier-2 受约束通用元素点击（分类器无法命名格子时，由程序筛出面板内通过危险动作黑名单的元素交给模型选，AI 不编造选择器）。三重限制：有效动作 ≤14、单字段 ≤60s、连续 3 次指纹无进展即停。执行前现场重定位节点，翻页方向不符记入观察。

**接管路由**（`fillDateWithAgent` 重构）：规则适配器先行（**0 次模型调用**，删除了原先"在 stop/write 间选择"的无效请求）→ 失败且实验开关开启 → **接管前脏状态检查** `inspectHandoff`：重读最终值、核对 peer 基线（在适配器尝试之前捕获，适配器改坏的另一端不会当成基线）、按几何锚定唯一归属现存弹层（adopt 纪律补齐 popup 状态）；状态不可解释 → BLOCKED。接管后 AI 从当前状态继续，不盲目重开面板。三种决策（规则/分类器/AI）共用同一套执行与验证：关面板 → 读回 → 提交值形态核对 → peer 与起止顺序保护。

**实站数据驱动的三层驱动与调用节约**（v0.9.0 实测：28 次模型调用累计等待 328 秒，占填写阶段 74.6%；成功 trace 主要是模型选 type）：

1. **无 AI 直接输入快路径**：输入框可编辑 + 精度已确认 + 目标有来源 → 程序直接输入、等提交、读回（0 次模型调用）；失败清掉半截值转交下一条路径，readonly/不可编辑控件自动跳过。
2. **年份网格本地预翻页**：目标年份不在当前年代范围（实站 5 个获奖时间的失败场景）→ 程序按方向翻页并核验方向（0 次模型调用），候选集同时给出 `nav-to-year`（"翻页使年份列表包含 2022"）供 AI 循环使用，避免模型请求不存在的 `pick-year`。
3. **非法动作受限纠错**：模型返回候选之外的 id 时，带 `invalidAction`（合法 id 清单）重问一次；再错则字段失败并记录 `INVALID_ACTION_ID` 证据（请求的 id + 当时候选集，全部是插件自产标识，不含页面内容）。模型仍受候选白名单与执行前复核约束，不放宽。
4. **精度只升不降**：精度只来自日历当前视图（无占位符/控件类型证据）时标记 structuralOnly——级联日历先显示月/年视图不代表页面只要月/年，出现更深网格即升级目标（月→日、年→月），防止出生日期被截断成 2024-09；占位符等静态证据优先，不会被视图升级覆盖。契约快路径在 structuralOnly 且精度非 day 时不启用（交给会升级的 AI 循环）。

**弹层未归属时 AI 仍可接管**（针对 v0.8.21 真实日志的主故障"未出现可识别的关联日历"）：归属失败不再直接放弃——observe 此时只给打开类候选（点击输入框、点击字段附近过安全黑名单的日历图标、等待），归属唯一确认之前不出现任何面板内部动作；AI 自己想办法打开日历后，结构分类与快路径照常接手。静态证据（占位符/控件类型）足够时精度先行解析，`type` 候选（输入框可编辑且非 readonly）随之可用；readonly 一律拒绝直接输入。每步的 lastAction 是动作反馈对象：intent（做了什么）+ before/after（动作前后的真实输入值与面板视图）+ outcome（PAGE_CHANGED / NO_CHANGE），模型据此区分"点击成功页面变化"与"点击无效"，无效时换候选而不是重复。观察负载瘦身：只发送日期导航需要的字段白名单（label/精度相关属性/段号），不再携带整条记录上下文。

**安全边界**：候选只引用已归属面板内元素；提交/删除/协议类控件一律拒绝（capture-autoclick 黑名单 + 命中点复核）；时分面板识别后立即暂停不给可点击候选；值永远来自上游有来源校验的匹配，Agent 只做"选哪个格子等于目标"的低幻觉任务。**无进展按动作结算**：连续 3 次「动作后页面无实际变化」（比较输入值与面板视图/表头，不按观察次数——interaction-agent 每步观察两次，按观察计会把换策略前的 AI 提前判死）才停止；中途换策略（失败后改点图标/换翻页方向）不受影响。**失败原因结构化**：`STALL_DETECTED`（无进展）、`PEER_CHANGED`（另一端被改）、`PRECISION_UNRESOLVED`（精度不定）、`BUDGET_EXCEEDED`（超时）、`TARGET_REPLACED`（控件被替换）各自有码，不再统统归为「值未确认」。失败证据沿用白名单（新增 `PRECISION_UNRESOLVED`、`HANDOFF_UNSAFE`、`PEER_CHANGED`、`STALL_DETECTED`、`BUDGET_EXCEEDED`、`GENERIC_AGENT_UNAVAILABLE`，不含选项文本与任何值）。

## 使用方式

侧边栏新增「**实验：未知日期 AI 交互接管**」，默认关闭。开启后：现有适配器先试，失败时未知日历交给通用 Agent（结构可分类则 0 次模型调用，否则 3-8 次模型调用逐步交互）。不开开关时行为与 0.8.21 完全一致。测试可用 `self.__APPLY_FILL_DATE_MODE__`（`adapters-only`/`agent-only`）与 `self.__APPLY_FILL_DATE_DISABLE_CONTRACT__` 强制指定臂别。

## 四组对照基准（tests/date-benchmark.cjs，10 个未知控件场景）

C 与 D 都注入同一脚本化"正确模型"决策器；D 的 0 调用来自快路径命中，而不是没接决策器。

| 组别 | 成功 | 误填 | BLOCKED | 失败 | 平均耗时 | 平均模型调用 |
|---|---|---|---|---|---|---|
| A 原适配器 | 0/10 | 0 | 0 | 10 | 182ms | 0 |
| B 通用规则（分类器+契约，0 调用） | 5/10 | 0 | 1 | 4 | 777ms | 0 |
| C 纯 AI 逐步（脚本化正确决策） | 7/10 | 0 | 1 | 2 | 908ms | 4 |
| D 规则优先 + 接管 | 7/10 | 0 | 1 | 2 | 1129ms | 1 |

消融结论（基准内含硬断言）：

1. **原有适配器在未知控件上全部失败**——这正是本轮要解决的架构限制，不是模型能力问题。
2. **仅靠通用分类器即可解出全部结构可分类场景（5/10），0 次模型调用**——大部分"未知"日历不需要 AI 逐步操作。
3. **D 混合臂拿到 B 拿不到的场景**：`icononly`（点击输入框无效，AI 点击字段旁的日历图标打开，5 次调用）与 `messy`（英文合并表头，契约失败后 AI 接管，1 次调用）——同时**在结构可分类场景保持 0 次模型调用**（day/month/far/confirm/async 全部走快路径）。
4. **纯 AI 臂与混合臂同为 7/10**：逐步决策补上规则盲区，混合架构不为此多花成本。
5. **没有任何一臂写进错误的日期**；值写进去但面板收不起的场景如实报 BLOCKED，不虚报成功。

脚本化决策只证明执行器在正确决策下能完成任务；**真实模型的测量协议**：固定同一模型与接口配置，在同一 fixture 与同一初始状态下独立重复 ≥10 次，统计字段成功率、误填率、单字段耗时、模型调用次数、接管成功率与人工介入比例，与上表对照。

## 边界与验证范围

- 本轮只接管**完整日期面板**；拆分年月仍由组合框/原生下拉驱动。拆分控件若先被扫描成文本输入，只有在控件附近存在有界候选列表证据时才升级到组合框驱动；候选必须被实际点击并通过提交核对。缺少这类证据时阻止普通文本赋值，也不把已有文本回显当成已选值，并记录 `OPTION_COMMIT_UNCONFIRMED`。
- `npm run test:split-date-routing` 覆盖通用年月下拉（包括月份 `1` 与 `10/11/12` 同时出现）和无下拉证据时的 fail-closed 行为。
- 截图观察未纳入（纯 DOM 结构观察）；视觉模型可作为后续增强。
- 分类器对虚拟滚动、canvas 渲染、Web Component 封闭阴影的日历不适用——这些会落入"无结构 → 停止"，不会误填。
- 真实站点验证清单：用「现场结构导出/自动采集」抓取目标站点的日期控件结构生成 fixture → 迭代分类器 → 开启实验开关实测教育经历开始/毕业时间、项目起止、获奖日期三类 → 把结果与边界补进本文档。在此之前，本功能仅作实验特性发布。
