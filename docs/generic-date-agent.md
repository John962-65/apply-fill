# v0.9.0 通用日期交互 Agent：规则优先 + AI 失败接管

本轮解决的核心架构限制：此前日期字段只给模型「调用适配器 / 停止」两个候选，全部日历操作由预先编写的平台适配器控制；遇到不认识的日历弹层时，模型既看不到面板结构，也没有可用的动作，只能放弃。0.9.0 把弹层观察、候选生成与逐步执行接进已有的交互引擎——AI 第一次能根据网页真实状态逐秒决定下一步，而不再要求开发者为每种日期组件写适配器。

## 接口改造（先于 Agent 本体）

- **`calendar-agent.js` 支持动态契约**：`fill({..., contract})` 新增可选参数。契约字段双形态——CSS 选择器字符串（目录契约原样兼容）或 **resolver 函数**（每次访问对当前面板重新解析，不缓存节点，杜绝"临时类名在重渲染后失效"）。`validateContract` 按声明的网格推导必需导航链，缺链即返回 `null` 交回调用方，绝不猜测。未提供 contract 时原路径不变。
- **`date-precision.js` 日期精度模块**：只信页面证据——控件类型与占位符写法 → 日历网格结构 → 提交行为（仅用于最终验证）。资料值形态**绝不参与推断**；证据冲突或不足时返回 unresolved，Agent 停止而不是按简历日期猜。资料值一律按页面精度归一化（资料存 `2024-09-01`、网页只要 `2024-09` 时按月填、按月验）。
- 现有四家适配器（ud/atsx/phoenix/calendar）内部逻辑未动；它们后续可从诊断里拿到精度判定依据，再按实证收紧。

## 通用日期 Agent（`date-agent.js`）

**结构分类器**（无平台类名依赖）：按格子文字与密度识别年/月/日网格（复用现成 `monthNumber`），解析表头年月（含「2026年10月」合并式表头），翻页按钮按 aria-label/文字识别，无标签时以几何箭头配对兜底——方向一律以点击后日历状态变化验证，不凭箭头朝向断言。分类产物是一个**活的 CalendarView**：每个访问都现查现用，绝不缓存节点。

**双策略**：

1. **合成契约快路径**：分类高置信时，把结构合成为与 control-catalog 同形的日历契约（三种视图无条件声明、resolver 活解析），交给现有 `ResumeProCalendarAgent` 驱动——**0 次模型调用**，未知但结构规整的日历约 250ms 完成。
2. **AI 逐步接管**：分类不置信或快路径失败时，走 `ResumeProInteractionAgent` 循环。候选分两层——tier-1 语义动作（pick-year/month/day、open-year/month-view、nav-*、confirm、type、wait、stop，全部只在目标唯一匹配时出现）+ tier-2 受约束通用元素点击（分类器无法命名格子时，由程序筛出面板内通过危险动作黑名单的元素交给模型选，AI 不编造选择器）。三重限制：有效动作 ≤14、单字段 ≤60s、连续 3 次指纹无进展即停。执行前现场重定位节点，翻页方向不符记入观察。

**接管路由**（`fillDateWithAgent` 重构）：规则适配器先行（**0 次模型调用**，删除了原先"在 stop/write 间选择"的无效请求）→ 失败且实验开关开启 → **接管前脏状态检查** `inspectHandoff`：重读最终值、核对 peer 基线（在适配器尝试之前捕获，适配器改坏的另一端不会当成基线）、按几何锚定唯一归属现存弹层；状态不可解释 → BLOCKED。接管后 AI 从当前状态继续，不盲目重开面板。三种决策（规则/分类器/AI）共用同一套执行与验证：关面板 → 读回 → 提交值形态核对 → peer 与起止顺序保护。

**安全边界**：候选只引用已归属面板内元素；提交/删除/协议类控件一律拒绝（capture-autoclick 黑名单 + 命中点复核）；时分面板识别后立即暂停不给可点击候选；值永远来自上游有来源校验的匹配，Agent 只做"选哪个格子等于目标"的低幻觉任务；失败证据沿用白名单（新增 `PRECISION_UNRESOLVED`、`HANDOFF_UNSAFE`、`PEER_CHANGED`、`STALL_DETECTED`、`GENERIC_AGENT_UNAVAILABLE`，不含选项文本与任何值）。

## 使用方式

侧边栏新增「**实验：未知日期 AI 交互接管**」，默认关闭。开启后：现有适配器先试，失败时未知日历交给通用 Agent（结构可分类则 0 次模型调用，否则 3-8 次模型调用逐步交互）。不开开关时行为与 0.8.21 完全一致。测试可用 `self.__APPLY_FILL_DATE_MODE__`（`adapters-only`/`agent-only`）与 `self.__APPLY_FILL_DATE_DISABLE_CONTRACT__` 强制指定臂别。

## 四组对照基准（tests/date-benchmark.cjs，9 个未知控件场景）

| 组别 | 成功 | 误填 | BLOCKED | 失败 | 平均耗时 | 平均模型调用 |
|---|---|---|---|---|---|---|
| A 原适配器 | 0/9 | 0 | 0 | 9 | 182ms | 0 |
| B 通用规则（分类器+契约，0 调用） | 5/9 | 0 | 1 | 3 | 657ms | 0 |
| C 纯 AI 逐步（脚本化正确决策） | 6/9 | 0 | 1 | 2 | 612ms | 3 |
| D 规则优先 + 接管 | 5/9 | 0 | 1 | 3 | 837ms | 0 |

消融结论（基准内含硬断言）：

1. **原有适配器在未知控件上全部失败**——这正是本轮要解决的架构限制，不是模型能力问题。
2. **仅靠通用分类器即可解出全部结构可分类场景（5/9），0 次模型调用**——大部分"未知"日历不需要 AI 逐步操作。
3. **纯 AI 在分类器失败的合并式英文表头场景（messy）上成功**——逐步观察与决策补上了规则的盲区，这是 AI 的独立价值。
4. **混合臂（D）与纯规则臂持平且模型调用为 0**——规则失败时接管不会增加可分类场景的成本。
5. **没有任何一臂写进错误的日期**；值写进去但面板收不起的场景如实报 BLOCKED，不虚报成功。

C 组用脚本化"正确模型"决策，只证明执行器在正确决策下能完成任务；**真实模型的测量协议**：固定同一模型与接口配置，在同一 fixture 与同一初始状态下独立重复 ≥10 次，统计字段成功率、误填率、单字段耗时、模型调用次数、接管成功率与人工介入比例，与上表对照。

## 测试与回归

- `npm run test:generic-date`：15 个浏览器场景——契约快路径、AI 循环、月精度（两条路径）、十年翻页、确认按钮（两条路径）、异步打开、面板收不起 → BLOCKED、时分面板拒绝、无结构停止、peer 保护、接管前检查、完整管线开/关。
- `npm run test:date-benchmark`：四组对照 + 消融断言。
- 全量回归：165 个单元测试与 popup-lifecycle、feishu-ud-captured、atsx、phoenix、published-controls（真实 rc-picker/Element/iView）、form、startup、auto-click-capture、browser-input、combo、grounded-fill 等浏览器套件全部保持通过。

## 边界与验证范围

- 本轮只接管**完整日期面板**；datePart 拆分年月控件、级联地区选择、原生 `type=date` 保持原路径。
- 截图观察未纳入（纯 DOM 结构观察）；视觉模型可作为后续增强。
- 分类器对虚拟滚动、canvas 渲染、Web Component 封闭阴影的日历不适用——这些会落入"无结构 → 停止"，不会误填。
- 真实站点验证清单：用「现场结构导出/自动采集」抓取目标站点的日期控件结构生成 fixture → 迭代分类器 → 开启实验开关实测教育经历开始/毕业时间、项目起止、获奖日期三类 → 把结果与边界补进本文档。在此之前，本功能仅作实验特性发布。
