# ApplyFill 2.3：General Form Interaction Engine

本阶段从 `80f009b` 继续，保留知识库、语义路由、重复经历身份、波次调度和已稳定的确定性执行器。不新增 ATS 规则或独立 Agent。新增的是处于原字段事务中的交互循环。

## 执行方式

1. 原有快路径尝试，并使用原有独立 FieldVerifier 判断正式提交。
2. 复杂控件未能完成时，读取交互模式。`off` 保持快路径，`local` 默认启用本地状态反馈，`ai` 在本地无确定策略时允许请求动作建议。
3. InteractionObserver 统一读取当前值、已提交值及来源、展开、忙碌、候选、焦点、验证状态和 DOMRevision。提交状态允许未知；输入显示、浮层关闭和模型回答都不证明提交。
4. 交互对象通过 `aria-controls` / `aria-owns` 或已有 PortalTracker 的关联证据定位。模型只看到不透明对象句柄；没有足够定位证据时停止，不扩展到整页按钮。
5. InteractionPolicy 每轮只选择一个动作。确定性策略处理焦点、键盘打开、唯一精确候选、搜索、活动候选提交和滚动；月份单位与日期的比较属于目标值语义，不依赖网站和组件类名。
6. InteractionActor 复核观察状态与节点，使用统一 Primitives 执行动作，然后按条件等待状态变化。旧观察过期时重新观察；目标节点被替换时撤销事务，交回原重定位流程。
7. 每轮独立验证。模型不能返回“成功”，不能提供任意 JS、选择器、输入文字或页面导航。正式值与目标匹配且稳定后才能完成。

快路径实际点击过的节点会作为反馈交给慢路径，避免立即重放无效点击。同状态中的动作去重，CLICK 与 SELECT_OPTION 的相同点击归为同一动作。原生点击无效果后才允许 Pointer/Mouse 备选，不伪造 `isTrusted`。

## 预算与用户接管

每次慢路径最多 8 个动作、6 秒、2 次模型请求，且仍受原字段总预算和租约约束。单次动作只在最多 350 ms 内等待可观察变化，不靠增加固定 sleep 判定成功。过期观察的重规划也有独立轮数上限。原有跨 Wave 重规划预算保留；慢路径失败不进入终态自动补填重试。

单次观察最多四个关联区域、60 个交互对象，每个区域最多检查 300 个节点。观察被截断时直接转人工，不在部分候选中声称找到唯一匹配。嵌套在同一语义候选内的按钮只记录为一个逻辑候选。

慢路径所属浮层的用户点击、编辑或键盘事件归属当前逻辑字段，立即触发既有 Guard 保护、撤销事务和模型请求取消。页面变化、取消、超时与人工接管后的迟到建议不会继续操作。

诊断增加 OBSERVE、DECIDE、ACT，记录本地/模型决策、状态变化、无进展、旧观察失效、预算耗尽和转人工原因，不记录目标值或原始观察正文。

## 模型边界与设置

工作台的“未知控件的交互回退”提供三种模式。默认本地模式不调用模型。AI 模式还需开启云端辅助并保存配置，沿用已有模型服务及授权。

候选目标值在本地比较，发送模型时以 `[TARGET]` / `matchesGoal` 标记。Background 再次做隐私复核，只发送白名单中的字段标签、控件角色、候选标签、目标标记和动作结果。不发送输入框值、业务提交值、原始简历、整页 HTML、URL、API Key 或可执行代码。模型只能从本次提供的动作列表选择下一步，错误输出和额外参数拒绝执行。每次请求不自动重试，最多等待 3 秒，并支持字段级取消。

这种最小化输入也意味着：如果本地无法将目标与候选建立可靠关系，模型不能靠猜测私有目标值选择候选；应转人工。第一版不声称能理解所有控件或所有目标值别名。

## 评测协议

运行前必须提交全部实现。评测脚本拒绝脏工作区，记录冻结的 engineCommit。同一提交通过配置切换策略，不修改网站规则。

```sh
pnpm evaluate:interaction
pnpm evaluate:interaction -- --mock-ai
APPLYFILL_E2E_BROWSER=edge pnpm evaluate:interaction -- --mock-ai
pnpm evaluate:interaction -- --manifest /absolute/path/to/heldout.json
```

默认 cohort 为 **synthetic-known**：原生 JS、React、Vue 的匿名靶场，覆盖非 option 按钮、焦点打开、键盘提交、二次确认、重绘、业务状态缺失、拒绝合成事件与重名候选。这些是参与开发的回归用例，不能证明未见网站的泛化能力。

`--mock-ai` 仅模拟 API 返回动作建议，不能当成真实模型效果。每个策略报告任务数、真实业务值可观察数、完成率、人工接管率、最终错误写入数、错误成功数、平均耗时与模型请求数，并保留逐项结果。错误写入只统计改变了原业务值且最终值错误的情况；未能读取独立业务状态时单列为不可观察，不把它算作错误率为零的证据。结果在 `packages/testbed/evaluation-results/`，不记录资料值。

业务完成率与人工接管率分别统计：即使评测器读到正确业务值，引擎自己无法验证时仍计为人工接管。二者不强制互补。

外部清单示例（仅使用有权操作的测试表单和匿名资料）：

```json
{
  "cases": [{
    "id": "heldout-001",
    "url": "https://public-test-form.example/application",
    "fieldLabel": "Gender",
    "factPath": "basic.gender",
    "goal": "男",
    "truth": { "selector": "input[name=gender][type=hidden]", "property": "value", "expected": "M" }
  }]
}
```

清单中的 selector 仅由评测器读取独立结果，不传给引擎或模型。字段未自动映射时，可通过现有“换来源”明确目标资料；字段根本未发现则报告 UNRECOGNIZED。每新增外部网站，先冻结实现，执行、保存结果与失败分类；不得先增加网站识别规则，也不得测完后改源码重跑并仍宣称同一轮盲测。

实际招聘网站的登录、权限、跨域不可注入区、无语义定位证据、不可观察业务状态及拒绝合成事件的控件仍存在边界。真实模型验证、外部控件盲测和真实招聘网站盲测必须分别报告，不能用本地回归成功替代。
