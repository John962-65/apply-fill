# 网页补充 AI 归纳（0.6.3）

## 使用流程

1. 在招聘网站补完信息，点击「采集到资料树」。
2. 插件先把原文保存到「待确认补充」，再使用已配置的模型接口归纳。没有配置接口、请求失败或手动停止，原文仍保留。
3. 待确认页展示建议的分类、经历、字段名，以及新增、更新、重复或归属不确定的提示。
4. 对已有经历，建议归属会预选，可修改；更新已有字段时仍显示新旧内容。重复内容可手动忽略。
5. 对新经历，点击「按建议新建记录」后，同批、同板块、同条目的相关字段可选中这条新记录；随后逐项确认并保存。
6. 超过 100 字的描述可查看 AI 摘要。摘要仅辅助阅读，入库默认保留网页原文，数字、联系方式、日期不由摘要替换。
7. 需要重试或处理余下内容时，在待确认页点击「AI 归纳补充」。有未保存编辑时先保存，再归纳。

例如：招聘网站的“任职主要职责”可以建议归入“工作经历 / 某公司 / 主要工作”；如果两段经历无法区分，建议保留为待确认，用户选择最终归属。

## 数据与边界

- 发送到用户配置的模型接口：本批待确认原文、同条目的学校/公司/项目/时间等辅助信息，以及现有记录的名称、字段和值。口令、验证码、密钥等在准备上下文时过滤。
- 每次最多归纳 50 项、参考 200 条现有记录，现有字段值最多发送前 2000 字；单次上下文上限 500000 字符。0.6.3 已移除插件的 60 秒自动超时。等待时显示已用时间；可在网页侧边栏或待确认页点击“停止等待”。停止等待不保证上游模型停止计算或计费。原始采集内容不会因为批次限制被删除。
- 模型只能提出建议；建议中的未知记录/字段编号、跨记录字段引用会降为不确定。重复输出同一采集编号和输入之外的编号不采用；不同值不能标为相同内容。
- 保存建议前再次核对上下文；归纳期间相关上下文已变化时拒绝旧建议，要求重试。未确认建议不参与填写。
- AI 分类和摘要可能有误，仍需人工确认。摘要不参与自动覆盖原文。规则校验不能证明模型语义判断正确。

## 验证

```bash
npm test
npm run test:ui
npm run test:forms
```

单元测试覆盖建议校验、原文保留、跨记录引用、秘密字段过滤、批次顺序、真实 worker 请求构造、HTTP 失败及过期上下文拒绝。

管理页浏览器回归覆盖：AI 建议预选已有记录、展示旧值、人工确认更新、新建经历的多字段归类、摘要不覆盖原文、接口失败后原文保留，以及原有备份/导入/导出流程。使用固定模型响应验证软件流程，没有调用真实收费接口验证模型质量。

0.6.3 回归另覆盖：模拟经过两分钟仍继续等待、主动停止立即返回、迟到响应不写回、浏览器中停止后按钮恢复，以及中断错误的中文提示。
