# v0.7.2 日历面板操作修复

结构快照给出了 ant-calendar-picker-input / ant-calendar-picker 的失败类名，计数为获奖时间 5、开始时间 7、结束时间 7。该快照是多次扫描合并结果，不能把其中的 ok 字段当作本次操作已成功，也未提供展开后日历面板的完整 DOM。

检查现有代码发现：日期操作会选择整页第一个可见日历；普通年月导航不支持月份面板专用年份按钮；翻页前缓存的标题节点可能在重渲染后失效。

本次修改：

- 优先通过输入框的 aria-controls/aria-owns 定位；否则只接受当前操作唯一新出现的面板。多个候选停止，不点击其它日历。
- 聚焦输入框并打开面板，等待异步出现。
- 分辨日历与月份面板。支持月份面板按年份翻页及中文月份格；普通日历支持按年/月翻页和明确日期标题。
- 翻页后重新获取面板、标题和按钮，等待年月发生变化，最多 60 次翻页。
- 点击后检查外部输入框，关闭面板后再次检查；不能仅因为面板输入框有文字就判为成功。
- 失败记录具体原因和操作步骤，例如面板不唯一、年月无法读取、翻页未生效、日期格不唯一、值未保留。

验证：71 项单元测试、原有表单浏览器回归，以及新加的月份跨年/异步加载/节点替换/旁边无关日历/日期格选择/点击无效测试通过。新日历是匿名模拟结构，不是荣耀登录页面复制品。未在荣耀实际账号内验证，不保证全部日期组件通用；没有结构关联且复用已有面板的控件仍可能停止。

更新扩展后刷新招聘页面。可以查看字段对照表中的“打开日历、识别日历、日历翻页、日历停止”记录。本版保留已有内容，不自动纠正历史误填日期。
