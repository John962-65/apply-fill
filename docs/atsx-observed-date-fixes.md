# 0.8.3：依据实际采集适配飞书日期组件

用户的 v0.8.2 控件采集揭示以下结构：

- 日期区间的两个点击位置是 `.atsx-date-picker-period-month-label`，每个内部又分 year / separator / month 三个 span。之前只查找叶节点中的完整 YYYY-MM，导致漏识别。
- 下方一个零尺寸隐藏 input 只作为内部焦点/存储位置，不是日期端点。
- 展开的是 `.atsx-date-picker-dropdown`，内部 `.atsx-date-picker-period-month-panel` 含两列 `.atsx-date-picker-period-month-panel-list`，年份四位数字，月份两位数字，均需滚动。不是 Ant calendar 的年月翻页网格。
- 采集中获奖年份另有 `.atsx-date-picker-panel-body-year`、年份单元格及两个分页操作图标。

修复：扫描具体的两个标签容器；选择年月使用两列列表。面板通过当前控件焦点与端点几何位置绑定，支持复用移动的弹层；每次点击、滚动和重新渲染后重新查找目标。读回核对当前端点以及另一端，禁止把跨端写入当成成功。获奖年份按真实年份网格和范围分页操作，校验翻页方向及最终值。保留日期来源和先后顺序校验。

验证：73 项单元测试、现有表单回归、7 种针对真实结构的浏览器场景（普通、弹窗复用、标签重建、拒收、延迟清空、写错端、候选重复）。新用例使用生产浏览器输入函数通过 CDP 发真实点击，模拟组件拒绝合成点击。验证两个起止端点互不干扰、另一条项目不被写入、获奖年份跨页选择。

边界：依据采集 DOM 重建组件结构和测试行为，未运行原站的组件 JavaScript，也未在用户已登录招聘页面端到端验证。年份/月份选项不在 DOM 或虚拟列表未渲染时会停止。获奖名称来源匹配拦截不是这次控件修复的范围。没有把用户的原始采集文件或个人内容放入发布包。
