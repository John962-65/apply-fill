# v0.8.18 搜索词与选中值分开核对

用户确认截图中的年份、月份只是输入了搜索词，没有点击候选；多张菜单仍展开。截图还显示，网页保留的项目名称与输入的日期来自不同记录。此次修复针对已复现的代码问题；尚未取得该登录页的实际 DOM，不能据此保证该网站已完全兼容。

## 原因与修改

- 通用下拉定位到 `sd-Select-container-*` 内层外壳就停止，而候选菜单可能位于外层 `sd-Dropdown-container-*`，与内层并列。现在在只有一个输入控件的范围内找到外层归属。没有列表类名或 ARIA 时，也只在这个控件内部识别有选项行的浮层，不在整页猜测同名文字。
- 搜索词及其显示镜像不代表选中。填写必须真实点击唯一候选；单选菜单必须因这个点击自行收起，选中显示或选择 ID 必须保留。点击无效、菜单仍开着、ID 未提交或随后回退都不算成功，也不把查询文字采集回资料树。
- 搜索年月时把 `09` 转为 `9`，能够找到 `9月` 候选，再按日期等价关系核对。已有未确认的数字查询可以改为有来源的目标年月；人工已确认的选中值、学校等字段中未确认的文本查询仍保留。
- 预读选项时，异步空菜单可能暂时没有尺寸和 ARIA。每次打开尝试结束都会发送关闭操作，不再因为暂时读不到面板就直接推进到下一项。
- 匹配时加入网页已经确认的名称、描述及日期。网页已有项目名称优先约束其日期来源；同校或同名奖项可以用已有专业、已选年月交叉确定。AI 给出另一条记录时，拦下并从实际对应记录补齐。现有名称不在资料里、候选不唯一或事实冲突时停止该条依赖记录的填写。人工已有内容保留。
- 写入前再次检查原有记录是否变化，变化时停止本条填写，请重新扫描。资料树原文、设置、扩展 key 与存储格式不变。

## 直接导出现场

展开侧栏「采集控件结构」，点击「直接导出当前控件结构（无需点击网页）」。无需重新点开卡住的控件或打开开发者工具。它只读取当前结构，不点击、不输入、不提交；文件中移除输入值和隐藏 ID 值，保留是否有值、有限节点结构、类名、几何位置及面板文字，可能包含页面显示的个人信息。不自动上传。

此功能优先记录上次失败的控件，并补充当前可见的控件；最多 24 个快照，每张有节点、深度上限。外层控件包含的无语义候选菜单也会出现在结构中。文件中的控件对应关系只使用局部或明确关联，不把其他已打开菜单归到本条记录。

## 验证

- `npm test`：148 项，包含已有项目与 AI 提议冲突、未知名称、重复候选、描述冲突、同校不同专业和同名奖项按已选日期确认。
- `npm run test:sd-query`：没有 ARIA、列表和选项类名的并列菜单。已有搜索词不算已有选中；真实候选点击后成功；拒绝点击、显示镜像但菜单未收起时失败，失败查询不被采集。
- `npm run test:split-resume` 的 `sd-sibling-existing` 模式：108 个字段，网页七条项目的顺序与 AI 提议不同。保留七个已有名称，补齐 87 个字段，核对 58 次真实选项提交、23 条完整采集日期；最后无残留菜单。另检查普通表单和选择后控件重建。
- 自动补全、普通下拉、Phoenix 枚举及来源核对的既有浏览器回归；采集测试检查并列菜单归属、文件输入值清除、网页内容不变、零控件点击与实际侧栏下载按钮。

以上浏览器测试使用匿名控件和真实 Chromium 输入通道，没有提交招聘申请。实际网站仍可能采用未观察到的弹层或选择状态，需要现场结构文件确认。
