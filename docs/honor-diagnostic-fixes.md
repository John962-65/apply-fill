# v0.7.1：诊断驱动的来源与分组修复

用户提供的 v0.7.0 字段报告显示：159 个字段全部归入工作经历、不同项目的日期来源串用、现居住地引用籍贯、无来源值仍能写入，以及多次下拉交互直接停止。报告包含真实简历，不纳入仓库。

本次修复：

1. 板块标题优先从字段所在的局部祖先容器寻找前置标题，排除导航；不再使用整个 form 的第一个标题覆盖全部字段。
2. 模型填写结果增加 sourceId，指定简历字段身份，再校验值的来源，避免单凭日期值全局回查产生归属歧义。
3. 无来源值停止写入；重复记录日期要求项目/学校/获奖名称的来源记录与日期一致；获奖时间、开始时间、结束时间分别校验来源用途。现居住地不能引用籍贯。
4. 协议、同意与承诺类字段交给本人确认，不执行模型或旧映射的自动操作。
5. 关闭弹层清除预读取状态，防止后来出现的其它弹层被旧观察基线关联。
6. 精确匹配不足时，向交互模型提供当前弹层中不重名的真实选项，并要求语义等价；允许“学校级/校级”等文字不同的表达被模型判断，不允许创造新选项。
7. 失败报告补充当前选项，诊断显示来源校验拦截数量。

验证：71 项单元测试；原有表单回归及新增同一 form 多板块分组回归；下拉规则/AI 模式的 16 个浏览器场景通过。模型响应采用模拟，没有真实荣耀账号和模型接口端到端验证。

未解决：报告中日期适配器多次操作后读回失败，仅靠字段报告不能确定具体日历 DOM、焦点状态或事件失败原因。本版没有宣称修复荣耀日期面板驱动，也不自动改动此前已经填错的内容。来源不明确的日期会留空；请核对历史已填项。
