# v0.8.21 交互引擎第一轮重构

本轮落实架构建议的三个优先项：弹层观察独立于平台类名、候选按需读取、局部失败经安全检查后隔离。保留现有日期适配器、CDP 输入通道与资料来源校验。

## 行为变化

填写前只观察已经展开且能归属到本字段的列表，不点击、不搜索、不滚动。未知选项仍标为 `unobserved`，不作为完整的空词表拦截匹配；实际填写时重新取得当前候选。AI 匹配和普通文本填写不再依赖最多 25 个下拉框的预读结果。

新增 `popup-controller.js`。`control-catalog.js` 提供单独的 ARIA 语义层，平台契约作为补充。弹层优先根据 `aria-controls` / `aria-owns` 归属，再检查单一控件内部的面板，最后观察本次操作中新出现或变为可见的候选。无类名的门户面板还需有选项结构并靠近触发器；存在多个候选时不猜测。观察器限制变化节点数量，每次关闭或结束填写后断开。

状态为 `CLOSED → OPENING → OPEN → SELECTING → VERIFYING`，失败进入 `RECOVERING`，收起失败进入 `BLOCKED`。隐藏、透明或被裁剪的缓存列表不作为打开证据；菜单曾实际出现且连续观察确认收起后，滞后的 `aria-expanded` 不阻止已提交结果。单纯滚动到屏幕外不算关闭。普通内联列表或网格不因带有 ARIA role 就被当作阻断弹层。组件重渲染时重新定位，不能继续点击旧节点。

搜索下拉依然要求真实选项点击、提交后的显示值以及稳定读回；存在隐藏选中 ID 时还须验证其变化。按 Escape 才收起的搜索草稿不算成功，也不采集回资料树。点击后的页面结果只能证明前端保留值，不能证明服务器已经保存。

## 局部失败与页面阻断

| 状态 | 处理 |
|---|---|
| 前一弹层正常收起 | 继续填写 |
| 唯一关联的局部菜单收不起 | 跳过后续受影响的复杂控件；检查独立文本目标 |
| 独立文本目标稳定、未遮挡、焦点可切换 | 继续写入并执行最终读回 |
| 同一日期区间、级联关系或菜单内目标 | 局部跳过，不拆开关系猜填 |
| 全局弹层、未知面板、遮挡或焦点锁定 | 暂停，未执行的字段标为“尚未尝试” |

不会为每个后续字段重复同一轮无效关闭动作。再次点击“一键 AI 填写”可以重新核对同一控件，已有内容仍受保护。来源归属、起止顺序、记录匹配和协议确认规则不变。

交互结果分别记录 `SUCCESS`、`SKIPPED`、`RECOVERED`、`BLOCKED`，布尔填写接口保持兼容。失败证据只保留字段编号、固定错误码、状态、候选数量、结构布尔值和恢复尝试；不附姓名、电话、选项文本、URL 或任意网页属性。结构导出带同一份脱敏证据，原有 DOM 导出的页面文字仍需按已有提示核对。

## 验证范围

- `tests/popup-lifecycle.cjs`：语义弹层、无类名异步搜索、透明缓存、ARIA 滞后、选项悬停时替换、两个弹层、无关结构变化、未提交就滚动离屏、搜索草稿未确认。
- `tests/feishu-ud-captured.cjs`：生产扫描、完整填写与真实 CDP。覆盖局部失败继续文本、其他复杂控件跳过、同一控件重试、全屏弹层、目标遮挡、焦点锁定、未知与预先打开的面板、日期不提交和反向翻页；匹配前没有打开任何菜单，资料树不改动。
- 单元测试验证失败证据的白名单；已有北森、UD 日期、拆分年月、浏览器输入、来源归属和结构采集回归继续使用。

UD 复现保留用户采集的类名和嵌套，使用匿名资料和测试事件。尚未在用户登录后的 NIO 页面完成整表验证。本轮没有加入截图驱动，也没有将所有日期和级联适配器迁入新状态机；它们继续使用原来的确认与区间保护。

## 更新

解压 `apply-fill-v0.8.21.zip` 覆盖原扩展目录，在扩展管理页点“重新加载”，再刷新招聘网页并确认显示 0.8.21。继续开启“实验：浏览器层点击与输入”。扩展 key 和资料存储不变，不需要重新上传简历。

实现参考：[W3C Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)、[Playwright actionability](https://playwright.dev/docs/actionability)、[CDP Input](https://chromedevtools.github.io/devtools-protocol/tot/Input/)。这些是语义和操作检查的依据，不提供招聘平台特有 DOM 的保证。
