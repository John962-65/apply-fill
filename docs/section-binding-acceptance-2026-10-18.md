## 一、实现内容

| 修改文件 | 当前行为 |
|---|---|
| `runtime/ContentRuntime.ts` | 按当前步骤的经历类型汇总所有区块，一次进行全局一对一重锚定；不再在每个区块分别认领同一批历史实例；MISSING 只在完成所有同类容器匹配后生成；containerIndex 为本步骤同类容器的全局序号 |
| `ContentRuntime.ts` 扩容 | 按同类区块已有槽位总数计算缺口；只有唯一添加入口时自动补足剩余数量；多个入口时报告 EXPAND_SECTION_AMBIGUOUS，不任意点击或分别扩容到简历总数 |
| `runtime/planner.ts` | 没有显式经历绑定的集合字段，若简历有多条候选，则规则、缓存和模型路径都转人工选择；项目切面使用同一保护；只有单条候选时保留直接填写能力；有 ResumeEntryId 绑定的区块按原绑定解析 |
| `ContentRuntime.ts` QuickFillPill | 新增来源选择提示与入口；用户明确选定具体路径后通过原有字段事务和验证执行，不把一次性跨经历选择学习成所有字段的默认来源 |
| `entrypoints/sidepanel/App.tsx` | 多个添加入口时显示可操作的中文提示：先手动添加需要的空白条目，再重新填写 |
| `tests/unit/planner.test.ts`、`e2e/section-scope.spec.ts` | 覆盖多候选来源拦截、单候选直填、多个区块首填/重绘/重排/用户保护、历史实例争用，以及唯一/多个添加入口 |

接口变化：没有新增后台消息或持久化格式；新增两种 mapping issue reason：`EXPAND_SECTION_AMBIGUOUS` 与 `RESUME_ENTRY_REQUIRES_CONFIRMATION`。单区块的 containerIndex 含义不变，多个同类区块的编号改为统一序号。字段身份仍由已确认的实例 ID 组成，不用区块序号作为稳定身份依据。

## 四、已知问题与当前限制

- 同类区块当前共同分配同一简历集合；特定区块只允许某类经历的业务筛选、独立子列表的来源选择、嵌套重叠区块仍需进一步实现和验证。
- 多个添加入口时保守转人工，不提供区块选择器；用户可先手动添加所需条目，再重新运行。
- 未绑定字段只有一个候选时可直接使用；多候选需要逐字段选择，尚无整区块的人工 ResumeEntryId 绑定界面。
- 未执行字段的来源歧义通过 mappingIssues 和 QuickFillPill 展示；SidePanel 的人工计数仍主要按执行结果统计，尚未统一全部未执行字段的计数口径。
- 本轮没有改变 ReanchorManager 的证据权重与阈值；当前专项通过不构成独立标注的重锚定准确率证明。
- SPA 无标记/长延迟步骤、Date 剩余异步分支、Background 调用方权限矩阵、原生存储永久挂起、子帧 JD 继承、简历/岗位版本、完整切面审核、附件报告和独立统计等缺口仍保留。
- 59 项设计任务、25 类控件、RA/WS/WL、五大 Gate、真实 ATS、独立 KPI 与远端 CI 尚未全部取得验收证据。
