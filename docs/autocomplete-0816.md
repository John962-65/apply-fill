# v0.8.16 搜索候选的点击与确认

用户截图显示学校、专业已有文字，但多张候选列表仍打开。截图无法提供实际 DOM、网站保存状态或插件运行版本；此次修复针对在代码中确认的同类问题，未宣称已验证该登录页。

## 原因

- 扫描器只把已知组件、搜索框和部分 ARIA 结构认作组合框。未知组件的 `input[type=text]` 会走普通文本通道，写入名称即被计入成功，没有点击候选。
- 某些组件把选中名称画在原来的可编辑输入框里，需要通过选项点击更新所选 ID。原组合框核对器只读独立显示区域，无法核对这类组件。
- 下拉关闭结果原来被忽略，且 Escape、页面外侧点击使用合成事件。有些组件因此留下弹层，遮挡后面的控件。
- 异步打开中的列表可能暂时没有高度，仍需依据本控件的 `aria-expanded` 等待或关闭，不能立即操作下一项。

## 修改

1. 在单个字段的范围内识别下拉/自动补全结构。支持输入框、只读箭头、局部候选列表与明确的 ARIA 关系。日期控件继续走日期驱动，原生 datalist 保留自由文本。
2. 只读取当前控件拥有的候选，学校、专业等结构兜底优先选择唯一完全同名项；学历、级别、年月保留已有同义词和日期分量匹配。不会点击“添加学校/专业”或同名的其他菜单。
3. 在点击前重新读取选项，使用现有浏览器输入通道操作。核对选中显示、组件隐藏的选择值，或“点击本候选后自动关闭且名称保留”的选择过程；仅有搜索文字不通过核对。
4. 对没有隐藏选择值的控件保留当前页面的选择凭据，供最后读回和补充采集使用。控件重建后按现有板块、条目和字段身份重新定位。
5. 收起菜单使用真实 Escape；不支持 Escape 时，只允许点击经浏览器两次核对的裸 `body/html` 背景。找不到空白背景时不点击其他表单元素。
6. 下一项开始前检查上一张列表是否已关闭。若仍打开或关联不唯一，暂停后续操作并在对照表说明原因；预读选项也遵守同样要求。
7. 上轮留下的同名搜索文字可继续完成选项确认；已确认的人工内容保留，不覆盖不同的待核对搜索文字。

## 验证

`tests/fixtures/autocomplete-resume.html` 使用匿名学校与专业，模拟两条教育记录、四段年月、两条获奖、学历及级别下拉。它不复制私有网站 DOM。

`npm run test:autocomplete` 加载生产扫描器、来源校验及填写按钮，模型/存储为固定测试回复，点击和输入使用真实 Chromium CDP。检查最终表单中的选择 ID、日期、名称、菜单关闭状态和原资料不变。覆盖 15 种场景：普通填写、无 ARIA 的 div 列表、四张残留菜单、选择后控件重建、输入后才出现列表、动态识别后重建、鼠标移入时替换候选、无隐藏 ID、人工已有选择、近似项、同名重复、拒绝提交选择、延迟回退、不同的人工搜索文字和菜单无法关闭。

测试断言没有点击其他菜单、添加全称或提交申请；未确认搜索文字不会计入成功或补充采集。相关单元、普通下拉、Phoenix、拆分日期、浏览器输入与填写流程回归同时运行。

通用组合框回归另覆盖已经展开的候选列表在搜索后移到页面顶层的情况；规则与 AI 两条路径都保留原字段的面板归属，已有的其他列表不会被误认成新候选。

本地复现可证明上述流程；该招聘网站的实际结构仍需插件“采集网页结构”导出的结果验证。

## 安装

将包解压覆盖原插件目录，在扩展管理页点“重新加载”，再刷新招聘网页，让新内容脚本接管。扩展 key 和资料格式未改变，原资料树、配置和备份继续使用。

填写这类自定义候选控件时，勾选“实验：浏览器层点击与输入”，使用真实浏览器输入通道。
