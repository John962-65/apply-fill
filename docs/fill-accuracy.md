# 0.6.1 填写准确性与回归测试

## 行为变化

- 普通下拉框的“请选择…”按空值处理，用户已经选择的真实选项仍保留。
- 提取包裹式 label 时剔除控件与选项文本，避免异步加载选项改变字段身份。
- 生日只能来自生日/出生日期字段，不再以日期形状匹配毕业、入职等时间。
- AI 给出的姓名、电话、邮箱、证件号、生日必须有用途与人员归属正确的唯一来源。找不到来源或有多个来源时拒绝；本地补空也要求唯一候选。
- 网页映射身份为板块、条目序号、字段；简历映射保存分类、记录、字段固定编号及兼容名称。来源删除、多个候选、网页身份重复或条目签名变化时不复用。
- 映射版本升级到 3。旧版本只清理映射，保留控件结构；重新填写并通过最终读回后学习。
- 异步原生下拉最多重试约 1.8 秒。控件被替换时重新扫描，仅绑定唯一、结构一致的目标；页面已有值仍不覆盖。
- 填完后等待 250 毫秒统一读回。重新渲染保留值算成功；页面丢弃值则报告失败，不学习该次映射。

## 重复运行

```bash
npm ci
npx playwright install chromium
npm test
npm run test:forms
npm run test:ui
```

已安装 Chromium 时可设置 `CHROMIUM_EXECUTABLE_PATH`。

`tests/fixtures/fill-accuracy.html` 是可直接打开的匿名表单页面，包含基本信息、地址、两段教育、两段工作及重新渲染区域。`tests/form-browser.cjs` 在 Chromium 中运行真实扫描器、AI worker 的校验流程、填写循环和读回逻辑，只替换 Chrome 存储/消息接口及模型响应。

| 场景 | 最终检查 |
| --- | --- |
| 非空 value 的占位下拉 | 实际选中“男” |
| 人工已有姓名 | 原文保留 |
| AI 将毕业时间当生日、虚构电话和邮箱 | 三项仍为空 |
| 省市联动延迟 650 毫秒并替换城市节点 | 实际选择浙江省、杭州市 |
| 两段教育及两段工作 | 各段学校、专业、单位、职位逐一正确 |
| 写入期间替换当前及后续输入框 | 当前值保留、后续值填到新节点 |
| 组件重新渲染并丢弃写入 | 实际为空，读回结果明确失败 |

`tests/fixtures/mapping-identity.html` 使用教育与工作板块中完全同名的开始时间，浏览器逐一验证四条记录映射后的实际值，并检查网页重复身份不复用。

单元测试额外检查同名跨板块映射、跨分类/记录取值、同值多来源、重复网页映射、已删除来源、旧映射清理及序列化保留身份。

## 边界

这些回归验证的是固定表单和真实插件代码，不代表所有招聘网站或真实模型均已验证。无法唯一定位的结构会跳过复用；超过等待窗口的异步更新及站点自定义控件可能仍需人工处理。最终读回是有界检查，不持续监控页面后续任意时刻的变化。

## 0.6.3 读回诊断修正

“已填写”数量现在只计最终读回通过的项；未通过的项单列，不再一律断言为页面覆盖或拒绝合成事件。字段对照表区分读回为空/占位、读回内容不同、控件替换后无法唯一定位。没有名称的控件显示板块、条目和扫描位置，不再以“请选择”概括所有失败项。脱离页面的旧节点不能通过最终校验。

这项修正改进统计与诊断，不代表修复了所有网站的下拉或日期组件。若具体网站仍标红，请提供网站网址、标红区域截图或打码后的字段对照记录以定位。
