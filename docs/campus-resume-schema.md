## 资料树结构

统一为“分类 → 记录 → 字段”。常用字段只是准备提示，不是平台必填判定。

| 分类 | 每条记录的常用字段 | 可选扩展 |
| --- | --- | --- |
| 基本信息 | 姓名、手机号、邮箱、出生日期、性别、现居住地 | 国籍、籍贯、户籍所在地、民族、政治面貌、通讯地址 |
| 求职意向 | 意向岗位、意向城市、毕业届别、可到岗时间 | 期望薪资、每周实习天数、可实习时长 |
| 教育经历 | 学校名称、学历、学位、专业、入学时间、毕业时间 | 学院、学习形式、学校所在国家/城市、平均绩点、绩点满分、专业排名、课程、研究方向、导师、毕业论文、备注 |
| 实习 / 工作经历 | 公司名称、职位名称、开始时间、结束时间、工作职责 | 成果、部门、工作地点；工作另有离职原因 |
| 项目 / 科研经历 | 项目名称、项目角色、开始时间、结束时间、项目描述、主要职责 | 成果、项目链接；项目另有技术栈 |
| 校园经历 | 组织名称、担任职务、开始时间、结束时间、经历描述 | 成果 |
| 获奖经历 | 获奖名称、获奖时间、获奖描述 | 奖项级别、获奖等级、颁奖单位 |
| 语言能力 | 语言、掌握程度 | 听说能力、读写能力 |
| 语言考试 | 考试名称、考试成绩、考试时间 | 证书编号 |
| 专业技能 | 技能名称、熟练程度、技能描述 | 使用年限 |
| 资格证书 | 证书名称、取得时间、颁发机构 | 证书等级、编号、有效期至 |
| 论文 | 论文标题、期刊或会议、发表状态 | 发表时间、作者顺序、链接、摘要 |
| 专利 | 专利名称、类型、状态、申请号、申请时间 | 授权时间、发明人排序 |
| 自我评价 | 自我评价 | 个人优势、兴趣爱好 |
| 家庭成员 | 成员姓名、与本人关系、工作单位、职业 | 联系电话 |
| 紧急联系人 | 联系人姓名、与本人关系、联系人电话 | 自定义字段 |

语言考试、专业技能、论文、专利等独立分类，以及绩点满分、获奖等级等细分，是插件的资料管理设计；没有宣称所有平台都原生包含这些模块。字段目录共 18 类。

## 使用

1. 重新加载扩展，打开“资料管理”。
2. 已有资料点击“秋招字段模板”，勾选缺少的分类，添加到当前编辑草稿。
3. 重复经历点击分类旁的“＋”，一所学校的本科与硕士、一项获奖分别建记录；新记录自带常用空白字段。
4. 已有记录进入详情后点“补齐本条常用字段”。“可添加字段”可逐个添加排名、链接等扩展项。
5. 填写、核对后点“保存更改”。未保存前可重新加载撤销。

新建资料默认建立常用分类，重复经历分类不生成虚构记录。空字段不进入网页填写来源。JSON 备份保留完整树和空字段；Excel 仍是旧版字段导入导出，不保证保留所有树元数据。

## 兼容与归类原则

- 旧字段的内容、编号、来源和待确认内容不改写；同义字段只阻止重复新增，不主动合并。
- 例如已有“学校”“开始时间”，教育模板不会再添加“学校名称”“入学时间”。学历与学位不视为同义词。
- 旧混合分类“语言与证书”不猜测拆分。先添加目标分类和记录，再用字段旁“归类”移动。出现多个同义字段会提示核对。
- 日期保持原始精度；只知年份就保留年份，不补造月份或日。结束时间可以是“至今”；倒序提示人工核对，不交换端点。
- 解析提示要求奖项名称成为独立字段，并将每条奖项、语言考试、证书编号归入各自记录。实际模型输出仍需核对。
- 内推码、志愿顺序、调剂意愿、利益冲突声明、真实性承诺等依具体申请确认，不预设为可跨平台复用的通用事实。
- 资料树结构调整后沿用原有缓存失效机制，页面重新匹配；不宣称本次资料树改动解决所有第三方控件操作问题。

## 验证

单元验证包括旧资料不覆盖、同义字段补齐幂等、相同学校多条经历隔离、奖项/考试按编号分条、日期倒序提示，以及奖项占位记录名不变成事实来源。
浏览器验证使用生产资料管理页和真实存储处理模块，模拟扩展通信与模型回复，检查编辑、保存、刷新、备份、添加分类/记录、空白模板和窄屏布局；不等同于真实招聘网站端到端验证。
