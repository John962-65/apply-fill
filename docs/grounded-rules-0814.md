# v0.8.14：放宽有依据的填写规则

此前把“原文必须逐字一致”和“候选必须只有一条字段”作为通用条件，会把正常转换、重复存储以及同一经历里的漏匹配拦下。现在根据字段用途、所属记录和实际证据判断，允许可复核的转换。

| 情况 | 新处理 |
| --- | --- |
| 教育记录的学历写“学士”，或学位明确写“学士/工学学士” | 本条学历可填写本科/大学本科，保留原文和推导依据 |
| 本条学位写工学硕士、理学硕士等 | 学位选项可选硕士；学历可推导相应硕士层次 |
| 校级与院校级、学校级；省级与省区级；全国级与国家级 | 仅在奖项级别中按同义写法匹配 |
| 一个下拉同时有原文项及同义项 | 优先唯一原文项，再找唯一同义项 |
| 同一记录重复保存相同事实 | 合并为一个候选，不因冗余副本停止填写；冲突值仍需核对 |
| 两条校园经历都担任干事，起始日期也相同 | 用各自名称或独立描述确认归属，再复用该记录的职务和日期 |
| 同校两段教育，学校名称相同 | 可用唯一专业等证据确认记录，不只依赖校名 |
| 已确认记录，但 AI 漏出学历、职务、日期、获奖级别或明确能力 | 从该记录有依据的字段补齐，避免反复要求人工填写已有资料 |
| 阅读与写作均明确为同一水平 | 可组合填写读写，记录两项来源；听力与口语同理 |
| 本人同一记录有相同手机号和电话，包括“微信同号”备注 | 作为同一个联系方式使用，实际填入明确号码 |

上传简历仍按标准资料树提取，保留原学位和引用。缺少学历时，本地依据本条明确学位生成学历候选，显示推导说明，进入人工核对草稿。AI 返回的本科虽不逐字出现在引用中，只要本条明确学位足以支持，也能核验；没有原文依据的学位不据此生成新学历。人工修改推导字段后清除旧说明。

已有资料不用重做，也不会批量改写。旧资料中的“学历：学士”在填写阶段转换为本科，并在字段对照表显示“学士 → 本科”。独立学位仅在本条教育记录内推导；全局最高学历不套到其他学校或阶段。旧缓存缺少推导及记录核验证据时，交给当前记录匹配流程处理。

仍需确认的情形包括：来源相互冲突、记录无法区分、跨经历日期、起止顺序异常、没有等价选项。荣誉学位、博士后、在读状态不当作普通已获学位；不从学历反推是否取得学位。考试分数不换算能力，阅读一项不代表写作，语言“良好”不擅自升级为“熟练/精通”。本人和联系人信息分开，真实性声明与协议继续由用户确认。

验证使用匿名页面与模型回复，运行实际扫描、来源校验、填写按钮、浏览器输入和最终读回。涵盖学位推导、旧资料不变、下拉同义项、同校阶段、同值职务、冲突记录及语言组合；资料管理页面检查推导展示、引用和待核对状态。未连接真实招聘账号或调用收费模型。

升级时解压 `apply-fill-v0.8.14.zip` 覆盖原扩展目录，在扩展管理页点击“重新加载”，确认显示 0.8.14，再刷新招聘及资料管理页面。扩展身份保持一致，已有资料与设置继续使用。
