# ApplyFill

一个免费的网申表单填写浏览器插件。

把自己的简历信息保存成 Excel，打开招聘网站的网申页面后，点击「一键 AI 填写」，插件会读取网页表单，并根据你的简历数据匹配姓名、手机号、邮箱、学校、专业、经历等字段。

如果手里只有 PDF 或 Word 简历，也可以先让 AI 帮你整理成 Excel 模板。

> 插件本身完全免费并开源。AI 功能需要你自己配置一个 OpenAI 兼容接口，接口是否收费取决于你使用的模型服务商。

## 小白直接看这里

不需要会代码，不需要安装 Python，也不需要安装 Node.js。

整个流程只有四步：

1. 下载并安装插件
2. 配置 AI 接口
3. 导入自己的简历
4. 打开网申页面，一键填写

## 1. 下载插件

推荐直接下载已经打包好的版本：

**[点击这里进入 Releases 下载最新版](https://github.com/John962-65/apply-fill/releases/latest)**

在 Releases 页面找到类似下面的文件：

```text
apply-fill-v0.5.0.zip
```

下载完成后，把 ZIP 文件完整解压到一个固定文件夹。

例如：

```text
D:\Tools\ResumePro\
```

后面浏览器会一直读取这个文件夹，所以安装完成后不要把它删掉。

## 2. 安装到 Chrome 或 Edge

### Chrome

在地址栏输入：

```text
chrome://extensions
```

### Edge

在地址栏输入：

```text
edge://extensions
```

然后按下面操作：

1. 打开右上角的「开发者模式」
2. 点击「加载已解压的扩展程序」
3. 选择刚刚解压出来的插件文件夹
4. 选中的那一层文件夹里应该能直接看到 `manifest.json`

安装成功后，扩展列表里会出现 **ApplyFill**。

建议点击浏览器右上角的扩展按钮，把 ApplyFill 固定到工具栏。

如果安装插件之前已经打开了网申页面，请刷新一次网页。

### 已安装用户如何升级

开发者模式加载的扩展不会从 GitHub 自动更新。管理面板会每天最多检查一次最新正式版本；发现新版时会显示下载入口，检查失败不会影响插件使用。

升级步骤：

1. 从 Releases 下载新版 ZIP
2. 解压后覆盖原来的插件文件夹；也可以解压到新文件夹
3. 打开 `chrome://extensions` 或 `edge://extensions`
4. 如果覆盖了原文件夹，点击 ApplyFill 卡片上的「重新加载」
5. 如果使用新文件夹，删除旧扩展后重新选择「加载已解压的扩展程序」

管理面板顶部也可以手动点击「检查更新」。版本检查只读取 GitHub Release 元数据，不会自动下载、执行或覆盖任何文件。

## 3. 第一次使用，先配置 AI

打开任意普通网页，然后点击浏览器右上角的 **ApplyFill** 图标。

插件会在当前网页中打开管理面板。

进入：

```text
AI 配置
```

需要填写三个项目：

```text
API URL
API Key
模型名称
```

插件支持 OpenAI Chat Completions 兼容接口。

例如使用 OpenAI 时，可以填写：

```text
API URL
https://api.openai.com/v1

API Key
你自己的 API Key

模型名称
点「获取模型」后从下拉里选，例如 gpt-4o-mini
```

然后点击「保存配置」。

API URL 填服务商给的 base 地址（如 `https://api.openai.com/v1`）或完整的 `.../chat/completions` 地址都可以。填 base 地址时，保存时会自动补全为完整地址并显示出来。

请尽量使用 `https://` 开头的地址。API Key 和发给 AI 的简历内容都会发往这个地址；`http://` 是明文传输，经过公共 WiFi 或不可信网络时可能被截获。填了 `http://` 远程地址时设置页会给出提醒，但不会阻止使用；本机地址（`localhost`、`127.0.0.1`）不会提醒。

填好地址和 Key 后点「获取模型」，插件会从该服务的 `/models` 接口拉取模型列表作为下拉候选，向量、重排、语音、图像这类不能用来对话的模型会被隐藏。拉不到列表（比如服务商不提供这个接口）也不影响使用，直接手动输入模型名称即可。

如果你使用其他兼容 OpenAI 格式的模型服务，把服务商提供的接口地址、API Key 和模型名称填进去即可。

### API 配置看不懂怎么办

可以把它简单理解成：

```text
ApplyFill
负责读取网页和填写表单

AI 模型
负责判断“这个输入框应该填什么”
```

插件不会赠送模型额度，也不会替你注册 API。

## 4. 把自己的简历导入插件

有两种方式。

### 方法 A：直接用 PDF 或 Word 简历生成模板

适合第一次使用的同学。

先确保 AI 配置已经保存，然后：

1. 打开插件管理面板
2. 点击「AI 解析简历」
3. 上传自己的 PDF、Word `.docx` 或 TXT 简历
4. 点击「开始解析」
5. 等待 AI 提取信息
6. 浏览器会自动下载一个 Excel 文件

生成的文件名类似：

```text
resume_parsed_20260901.xlsx
```

建议先打开这个 Excel 检查一下。

AI 可能会漏掉少量信息，也可能把个别字段理解错，直接在 Excel 里修改即可。

确认后回到插件：

```text
模板管理
→ 导入 Excel
```

选择刚才生成的 Excel。

导入成功后，这份简历就会成为当前模板。

### PDF 解析失败

文字版 PDF 会先由插件内置的 PDF.js 在本地逐页提取文字，再把提取出的文字发送给你配置的 AI 接口。模型不需要直接支持 PDF 或图片输入。

如果 PDF 解析失败，请按插件的实际提示区分扫描件、加密文件和无效或损坏文件。可以：

1. 换成 Word `.docx`
2. 换成 TXT
3. 先用 OCR 工具识别扫描件，再重新导出为文字版 PDF
4. 移除 PDF 密码后重试
5. 将 PDF 页面转成图片，再使用明确支持图片输入的视觉模型处理

PDF、Word 和 TXT 都会先在本地读取或提取文字，再发送给 AI 整理。插件不会把 PDF 文件本身作为图片直接发送给模型。

### 方法 B：自己制作 Excel 模板

如果你愿意自己维护数据，新建一个 Excel 文件即可。

第一行固定写三列：

| 一级分类 | 字段名 | 值 |
| --- | --- | --- |
| 基本信息 | 姓名 | 张三 |
| 基本信息 | 手机号 | 13800000000 |
| 基本信息 | 邮箱 | example@qq.com |
| 基本信息 | 性别 | 男 |
| 教育背景 | 学校 | XX大学 |
| 教育背景 | 专业 | 材料科学与工程 |
| 教育背景 | 学历 | 硕士 |
| 教育背景 | 入学时间 | 2023-09 |
| 教育背景 | 毕业时间 | 2026-06 |
| 实习经历 | 公司 | XX公司 |
| 实习经历 | 岗位 | 研发实习生 |

保存成 `.xlsx`，然后在插件里点击「导入 Excel」。

目前也支持 `.csv`。

第二列「字段名」不要留空。

建议把信息拆细，例如：

```text
学校
专业
学历
入学时间
毕业时间
```

比把所有教育信息塞进一个单元格更容易匹配网页表单。

## 5. 开始填写网申

准备好模板和 AI 配置后：

1. 打开公司的网申页面
2. 如果页面之前已经打开，刷新一次
3. 页面右侧会出现 ApplyFill 填表助手
4. 在「当前模板」选择要使用的简历
5. 点击「一键 AI 填写」
6. 等待匹配完成
7. 检查填写结果

插件会扫描当前页面可以填写的字段，将网页上的字段名称、选项等信息和你的简历数据进行匹配。

填写成功的字段会短暂高亮，同时插件会提示本次填写了多少个字段。

**提交网申之前请自己完整检查一遍。**

不同招聘网站的表单实现差异很大，AI 填写只能作为辅助。

目前已经对普通输入框、文本框、下拉框、单选框，以及部分日期选择器和级联选择控件做了兼容。遇到高度定制的网页控件时，仍可能需要手动填写。

## 6. AI 没填上的字段怎么办

ApplyFill 还提供一个很好用的手动辅助方式。

例如网页上的「学校」没有自动填上：

1. 先点击网页里的「学校」输入框
2. 再点击 ApplyFill 侧边栏里的「学校」字段

插件会尝试把对应内容直接填进刚才点击的输入框。

如果网页控件无法直接写入，插件会把内容复制到剪贴板，你可以直接按：

```text
Ctrl + V
```

手动粘贴。

所以即使某个招聘网站的自动填写兼容性一般，也可以把 ApplyFill 当成一个随手取用简历信息的快捷面板。

## 7. 多套简历怎么用

插件支持同时保存多套 Excel 模板。

例如你可以准备：

```text
研发岗位.xlsx
产品岗位.xlsx
国企岗位.xlsx
英文简历.xlsx
```

全部导入后，在填写不同岗位之前切换「当前模板」即可。

如果某份模板有更新，可以点击模板卡片上的「重新导入 Excel」覆盖原来的内容。

注意顶部的「导入 Excel」是**新建**一份模板，不是覆盖。用同一个文件名重复新建时，插件会自动加上 `(2)`、`(3)` 后缀，避免列表里出现两张看不出区别的卡片。

### 怎么确认改动生效了

在 Excel 里补完字段再导入后，看一眼提示条上的字段数：

```text
模板已覆盖，字段 62 → 65 个。
```

如果提示是「仍是 62 个字段，数量没有变化」，通常说明选中的不是改完保存后的那份文件。常见原因是同一天重复解析简历，浏览器把新文件存成了 `resume_parsed_20260901 (1).xlsx`，而你改的是另一份。

如果提示是红色的「导入失败」，那么这次导入完全没有生效，模板还是原来的内容——按提示里给出的行号修好 Excel 再导入一次即可。

## 常见问题

### 安装后网页右边没有 ApplyFill

先检查：

1. `chrome://extensions` 或 `edge://extensions` 中 ApplyFill 是否已开启
2. 网申页面是否已经刷新
3. 当前页面是不是浏览器内部页面

例如下面这些页面无法注入普通扩展内容：

```text
chrome://extensions
chrome://settings
edge://extensions
```

请到普通网页测试。

### 提示“请先配置 AI 接口”

检查这三项是否都填写并保存：

```text
API URL
模型名称
API Key
```

### 提示“AI 接口请求失败”

常见原因：

1. API Key 错误或失效
2. API 余额不足
3. 模型名称写错
4. API URL 写错
5. 服务商接口并不兼容 OpenAI Chat Completions
6. 当前模型没有权限使用

### Excel 导入失败

请确认：

1. 文件是 `.xlsx` 或 `.csv`
2. 第一行是表头
3. 前三列依次为「一级分类 / 字段名 / 值」
4. 每一条数据的「字段名」都有内容

插件只读取第一个工作表。

导入是「全有或全无」的：只要有一行缺「字段名」，整个文件都不会生效，模板保持原来的内容。提示条会一次列出所有出问题的行号，按行号补好再导入一次即可。

如果出问题的行特别多，提示会变成「共 N 行缺少「字段名」」并提醒检查整列——这种情况通常是插入或删除列时把第二列整体挪位了。

手工编辑表格时最容易漏的是只填了「一级分类」和「值」、忘了中间那列。

### AI 填错了怎么办

直接手动修改即可。

自动填写完成后一定要检查，尤其是：

```text
日期
学历
证件类型
政治面貌
城市和地区
级联下拉框
多段教育或工作经历
```

这些字段在不同招聘网站上的结构差异较大。

### 某个网站完全填不了

欢迎提交 Issue：

**[提交问题或兼容性反馈](https://github.com/John962-65/apply-fill/issues)**

如果方便，建议提供：

```text
招聘网站名称
具体页面类型
无法填写的字段
错误提示
页面截图
```

请记得遮掉姓名、手机号、邮箱、身份证号等个人信息。

## 隐私说明

简历模板、「我的信息」、AI 配置，以及侧边栏的位置和折叠状态保存在浏览器本地的扩展存储中，插件不收集。

仓库里不包含任何真实用户简历数据，测试数据均为匿名示例。

使用「一键 AI 填写」时，插件需要把待匹配的网页字段信息，以及当前简历模板和「我的信息」中的相关字段发送到你自己配置的 AI 接口。名字像密码、验证码的补充字段不会发送。

**字段标签有可能是你自己的值。** Moka、北森这类平台的输入框没有 `<label>` 关联，通用标签解析会退到「相邻元素的文本」，而那个位置显示的往往正是你已经填进去的东西（学校、专业、出生年月…）。插件对此做一层可信度判定：有 `data-label`、`<label>` 关联或 `aria-labelledby` 的算可信；没有真关联、而那段文本又正好等于页面上某个控件当前值的，判为不可信并**丢弃标签**，只保留 `name` 和数字打码后的 `id` 这类结构标识。被丢弃的标签既不会带着值发给接口，也不会进结构快照；对照表里这类字段会显示「标签取不到：位置上的文本是你的值」。

使用「把本页已填内容加进模板」时不会发送任何网络请求：读回来的网页内容只在本地比对，确认后写进本机扩展存储里的模板。

使用「AI 解析简历」时，PDF 和 Word 会先在浏览器本地提取文字，但提取出的文字仍会发送到你配置的 AI 接口进行解析。不要把“本地提取”理解为“简历内容完全不会上传”。

因此，请自行确认所使用 AI 服务商的隐私政策和数据处理规则。

API Key 请勿分享给他人，也不要提交到公开 GitHub Issue。

- 多套 Excel 简历模板导入和切换
- 「我的信息」：籍贯、户口、家庭成员这类简历里没有的字段填一次，所有网站共用
- AI 自动匹配网页网申字段
- PDF / Word / TXT 简历 AI 解析
- 自动生成标准 Excel 模板
- OpenAI 兼容接口自定义
- 普通输入框、文本框、下拉框、单选框填写

- AI 填写结果高亮提示
- 页面内常驻管理面板

### AI 填写耗时与诊断

点击「一键 AI 填写」后，按钮显示扫描、AI 匹配秒数和填写阶段。完成或失败后，展开的「填写诊断」保留扫描、匹配往返、API（含响应体读取）、填写和总耗时，以及字段数量和用户 prompt 字节数；可在只读文本框中选择复制。未执行或未取得的阶段不会显示成零耗时。

- AI 等待超过 90 秒仅显示慢响应提醒，不自动取消。用户可随时点击「取消 AI 等待（保留本地匹配）」主动终止请求，包括响应体读取；取消不保证上游停止计算或停止计费。浏览器扩展生命周期、网络或上游服务仍可能自行中断请求。
- v0.3.0 需要 Chrome / Edge 116 或更新版本，并使用 `offscreen` 权限。AI 网络请求由扩展隐藏文档中的独立 Worker 执行，不放在 Service Worker 中等待响应头；简历解析也使用同一请求进程。浏览器退出、扩展重载仍会中断任务。
- HTTP、网络、用户取消、返回格式错误分别提示。AI 失败或手动取消时仍使用已验证的本地匹配结果，明确显示部分完成；不会自动重试或更改用户接口配置。慢响应提示说明可能与上游模型、中转、网络和输入量有关，不在缺少实测证据时断言一定是上游故障。
- 对明确的教育、工作、项目等字段，只发送相关的完整简历分组，保留多段经历及其关联字段。含糊、跨领域或无相关候选时回退全量，自定义未知分组始终保留。不采用固定 Top N 截断。
- 诊断摘要只包含版本、计数、字节数、耗时和标准错误类别，不包含接口地址、API Key、简历内容或上游错误原文。截图时仍需注意周围网页和模板本身的个人信息。

目前不做本地立即填写 / AI 异步补齐，不修改简历解析请求。请求大小下降不代表实际延迟按比例下降；真实模型的准确率和耗时仍需在同一模型、接口及表单上对比验证。

### 谁决定填什么

判定权在 AI，脚本只负责写。一次「一键 AI 填写」的顺序是：

1. 扫描网页上所有可填字段，**一次性全部送给 AI** 判定该填什么。字段除了标签和下拉选项，还带一个「第几段经历」的序号：页面上有 5 个项目块时，5 个「项目名称」会分别标成第 1 到第 5 段，模型才知道每段的数据该填进哪一行。判定看结构不看类名 —— 同一父节点下 2 到 12 个同标签兄弟、每个都含至少两个已扫描字段、并且各兄弟的字段标签集合完全相同，才算一组重复条目；所以用普通 `div` 堆出来的项目块也认得出来，而基本信息那种一行一个字段的布局不会被误判。
2. AI 没给出值的字段，才轮到本地规则补空。规则只处理姓名、邮箱、电话、性别、出生日期、身份证、籍贯、地区这 8 类硬事实，并且要求**简历里那条字段自己就写着这个用途** —— 值像号码不算数，QQ、微信、学号不会顶替联系电话。宁可留空让你补，也不填一个看着对的号码。
3. 接口失败、超时或你点了取消，AI 一项都没给值，此时全部字段都走第 2 步的规则，姓名电话邮箱仍然填得上（提示会写明「部分完成」）。
4. 真正把值写进网页的始终是本地代码。**日期类控件按人敲键盘的顺序填**：先真的 `focus()`（这一步决定组件把值提交到哪一段，只改值不聚焦就会提交到上一次活动的那一行），再写值、派发回车、失焦。认不出容器类名的日期框靠写法识别 —— 占位符像 `YYYY-MM`、或标签是起止时间／开始时间／结束时间／毕业时间这一类。级联下拉按层级等选项加载。单选框按 `name` **加上最近的分组容器**共同判定：有站点把「性别」和「是否接受X」两组用了同一个 `name`，只认 `name` 会把四颗并成一组，填其中一组就把另一组顶掉。AI 不接触网页。
5. 页面上没有原生控件的**自定义下拉**（Ant / Element / Fusion / Arco / Semi / MUI 这类 div 拼出来的组合框，性别、国籍这种）会被认成一个字段，填写时点开它、读新渲染出来的选项列表、匹配上就点那一项。护栏是：只认组件库容器和 `role=combobox`，只点触发器和选项本身；选项里找不到匹配就按 Escape 收起、保持原值不动；连标签都取不到的控件直接跳过，并在对照表里报出数量，不会静默消失。**插件始终不点提交、保存、删除这类按钮。**
6. **全部填完后再统一复读一遍**。上一条解决了大部分成对起止时间串行，但组件实现千差万别，这里留一张网：读回来的值正好是别的字段该填的，就判定为串位，在页面上标红，状态条会写「N 项写进去被页面顶掉了值（其中 M 项是和别的行串了值）」。**出现这个提示时，提交前必须逐个核对那几项。**

填写结束后，侧边栏的「字段对照表」逐行列出每个网页字段的结果：

```text
[个人基本信息] 联系电话 → 已写入 · AI · 简历字段「手机号码」 = 13800000000
[个人基本信息] 民族 → 写了但页面没认（当前显示：空） · AI · 简历字段「民族」 = 汉族
[教育] 开始时间 → 值是别的行串过来的（当前显示：2020-09-01，本该填「开始时间」） · AI · 简历里找不到出处 = 2024-09-01
[教育] 成绩（GPA）绩点 → 已写入 · AI · 截自简历字段「成绩」 = 3.15
[个人基本信息] 期望工作地点 → 没写进去（选项里没有「深圳」） · AI · 简历里找不到出处 = 深圳
```

来源分五档：值原样出现在简历里、只是写法不同（`2027-06` 对 `2027-06-01`，算同一天）、从某条简历值里截出来的一段、按某条改写或截短过的、以及**完全找不到出处** —— 只有最后一档是模型自己写的，会单独告警。「写了但页面没认」是值写进去了、控件按自己的状态又渲染回原样，常见于高度定制的下拉和日期控件，需要手动填。「填写诊断」仍然只有计数和耗时，不含简历内容；对照表含简历内容，所以默认折叠。

### 平台结构快照

每次填写结束后，插件顺手把**这一页的表单结构**记成本地的一条记录：

```json
{ "label": "学历", "control": "combobox", "drive": "open-pick",
  "options": ["博士研究生", "硕士研究生", "大学本科"], "recordTotal": 2, "result": "ok" }
```

- `drive` 是最有价值的一条：同一个「学历」下拉，A 公司能直接赋值、B 公司必须点开再选；日期框是原生 `type=date` 还是要「聚焦→敲键盘→回车」。这些是踩过的坑，记下来下次不用重新试。
- `options` 是点开下拉时实际看到的候选项原文 —— 平台定义、跨公司稳定，也正是 AI 最容易编错的地方。
- **不存填写内容**：只存标签、`name`、打码后的 `id`、占位符、控件类型、驱动方式、选项原文、分段数和「这次有没有真的生效」。标签不可信（那段文本其实是你的值）时会被丢弃，四个标识都没有的字段直接不进快照；控件 id 里的数字统一换成 `#`，免得把候选人编号带进去。存在扩展本地存储的 `formStructures` 键里。
- **可搜索组合框的历史记录会被剔掉**：像「毕业院校」这种要先打字才出候选的框，点开显示的是你以前填过的学校，不是平台词表 —— 等于页面上某个已填值的选项不会进快照；民族、政治面貌、省市那类平台自带的完整词表照常保留。
- 这条修复之前采的快照里存着你的值。插件读取时会**直接丢弃没有版本标记的旧条目**，重新跑一次填写就是干净数据。
- 同一平台按字段标识重合度（≥0.75）合并成一条并累计看到次数；能用来判定的标识少于 4 个时不判定为同一模板。最多存 30 条，超出淘汰最旧的。认平台的线索是主机名、脚本来源和容器类名：飞书招聘、Moka、北森这类平台用自有域名托管候选人表单，主机名本身就是最强特征；另一些平台嵌在企业自己的域名下，那种只能靠类名和脚本来源认。
- 侧边栏「平台结构快照（只有表单结构，不含填写内容，可复制）」里是 JSON，可以整段复制。

### 平台映射：同一套表单第二次直接填

上面那张结构快照同时还承载**对应关系**：某个平台位置该填哪条简历字段。

- **建立方式**：每次「一键 AI 填写」跑完就学一次 —— 这次填对且复读通过的位置，本身就说明了「这个平台的这个标签对应模板里哪一条」，当场记进快照。点「把本页已填内容加进模板」时还会再做一次（拿页面上的每个值回查简历），所以你在网页上手工改对的那几格也是在那一步被认下来的。只记**出处唯一**的位置：模型编的值、一条值同时对上好几个模板键的，都不记，免得把映射带偏。采集那一路的「对得上」只认**原样相等和写法不同**两档；从一句话里截出来的值不算对应关系，因为那是模型动过内容。
- **存的是字段名，不是值**。记成「这个位置 ← 简历字段『学校』」，下次现查现取。这样你换模板、改 GPA、加项目都不会让映射过期。
- **生效方式**：同平台填写时命中的字段直接按那条简历字段填，**不再送模型**；对照表里这类行标成「快照映射」，状态条会说清有多少项走映射、AI 只收了剩下多少个字段。全部命中时一次请求都不发。
- **对不上就回落**：某条映射连续落空三次（写进去了但页面没认），会被自动删掉并在状态条里点名，下次这些位置回落 AI。
- **段签名兜底**：映射挂在「板块 + 字段标签 + 第几段」上，并带着那一段的字段集合签名。如果这家公司在这一段里加了自定义字段、导致段号错位，签名就对不上，整段回落 AI，不会拿旧映射去硬填新结构。
- 认不出平台（`unknown`）时不套用任何映射 —— 两个 `unknown` 之间互相误配比不填更糟。

映射和结构一起躺在同一条快照里，导出 JSON 时能看到每个字段的 `resumeKey`（对应哪条简历字段）、`hits`（命中次数）、`misses`（落空次数）、`result`（这次是 `ok` / `failed` / `untested`）。

导出的快照里还有一段 `unrecognized`：**需要补驱动的控件线索**，三类都会收进来 —— 认不出来的（取不到标签的下拉、标签位置上显示的是值、完全没有标签线索的输入框）、**写进去了但被页面顶掉的**、以及**标签退化成占位符的**（`YYYY-MM` 这种，说明真标签没找着）。每条带类名链、`role` / `type`、控件类型和重复次数，相同的合并计数；**不含任何填写内容**。字段对照表的「需要注意」里也会点名前 6 条。

这一段是为了让你不用去 F12 里复制 outerHTML：哪家网站上还有字段莫名空着、或者写进去被顶掉，跑一次填写、把快照或对照表发回来，就能直接看出该补哪个选择器、该换哪种驱动方式。

### AI 辅助新增条目（实验功能）

当网页只显示一条论文或经历时，可点「AI 辅助新增条目（先预览）」。插件把候选新增按钮的编号、类型和条目数量交给 AI 规划；此阶段不发送简历正文。你确认新增清单后，插件逐次点击、检查新输入框出现，再重新扫描并请求 AI 填写这些分组的空文本字段。

- 支持范围：明确标注的论文、教育经历／教育背景、工作经历、项目经历。需在 `section` 或 `role=group` 分组内，有匹配标题、独立 `fieldset` 条目及唯一的 `button[type=button]` 新增按钮。每次最多新增 5 条；结构不明确时回退手动操作。
- 若模板没有正式「工作经历」记录，会用「实习经历」推导通用工作分组的条目数，兼容默认解析格式；两类同时存在时不自动混合，实习分组需另行核对或手动处理。
- 只允许枚举到的新增按钮与本地数量上限。AI 不能提供代码、任意选择器、导航、提交或删除操作；页面文本只作为数据。可在规划和新增期间停止。
- 只填相关分组的空文本框／文本域，写入前再次检查已有内容；写入后短暂等待并读回值确认。下拉框、日期等复杂控件暂不纳入这个辅助模式，仍可手动填写。短时读回不等于网站服务端已保存，提交前必须核对。
- 按钮变化、条目数量异常、网页重建已有字段或 2.5 秒内未确认新增，立即停止，不重复点击。已经新增的空条目不自动删除；网页自己的新增操作可能触发保存，确认前请留意。
- 这是可选辅助入口，不改变原来的「一键 AI 填写」方式。通常需要两次模型调用（规划 + 匹配），并非所有招聘网站的通用自动投递代理。

### 把本页已填内容加进模板

网申页上常常有一批模板里根本没有的字段（血型、英语等级考试分数、紧急联系人关系…）。这些字段 AI 只能留空或猜，你只能在网页上手填，填完还留在这一家公司的页面上，下一家重来一遍。

这个入口就是把它反过来：在同一个页面上把表单填完（包括你手改的部分），点侧边栏的「把本页已填内容加进模板」，插件读回各控件当前的值，列出模板里还没有的那几项，你勾选确认后按「一级分类」追加进当前模板。下次任何网站做「一键 AI 填写」，可匹配的字段就多了。

几条边界：

- **只读页面，不发请求。** 采集、判断、合并全部在本地完成，不会把网页内容发给 AI 接口，也不发送任何网络请求。它也不点击网页上的任何按钮，不碰提交操作。
- **只新增，不改动模板里已有的值。** 网页上填得和模板不一样时（哪怕是你在网页上改对的），这一项只会出现在折叠的「模板里已有的字段」清单里，标明模板现在存的是什么，不会覆盖。要改值请去管理面板改。
- 下拉框和单选框存的是页面上看得懂的选项文本（`男`、`硕士研究生`），不是控件内部的值。日期选择器的值会归一成 `2026-06` / `2026-06-30` 这种写法。
- **多段经历里的同名字段按段号写入。** 网页上有三个「项目名称」时，会写成「项目名称1、项目名称2、项目名称3」这样的行（和 AI 解析简历时已有的 `-学校 (2)` 编号约定一致）。只有当插件认不出这是重复条目结构、分不清第几段时，这几项才整组跳过、只报告 —— 把第三段的名字写成第一段，比这一项空着更糟。
- 「我的信息」里已经有字段名但还是空的（比如最高学历从来没填过），不会重复加进模板，插件会在提示里告诉你是几项，去管理面板补值即可。
- 密码、验证码、令牌这类字段一律不回写，勾选框不参与采集。
- 一次最多采集 30 项，超出的分批点。
- 分组名取网页板块的标题（`<h2>`、`<legend>` 这类），能对上模板已有分组的就沿用（网页写「教育经历」、模板写「教育背景」算同一个），对不上且标题很短的就把网页标题当成新一级分类，实在没有依据的落到「基本信息」。分组合不合适应在管理面板里过一眼。

确认写入后提示会显示 `字段 62 → 65 个`。**扩展存储里的模板才是填写时用的那份数据**；磁盘上原来的 .xlsx 不会被改动，浏览器扩展没有覆盖本地文件的能力。需要新文件时，在管理面板点这份模板的「导出 Excel」，会下载一份 `模板名.xlsx`（同名时浏览器自己加 `(1)`），导出的表头和列序与导入完全一致，可以再原样导回来。

profile-fields.js      「我的信息」字段表，以及回写模板时的字段判定和追加

tests/                 单元测试
icons/                 插件图标

### 关于侧边栏的「保存岗位到本地」「确认已投递」

`link/` 是连接桌面程序的代码。本版本不提供桌面程序，这两个按钮会提示需要桌面程序，直接忽略即可——**除这两个按钮之外的一切照旧**：模板、AI 填写、手动取消都不依赖它。
